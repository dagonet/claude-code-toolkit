# v4.1.2 — the v4.1.1 rollout patch (design)

**Status:** spec, branch `v4/1.2` (cut from `main` at eef4277 = tag v4.1.1). Written 2026-09-23 from the five consumer sync reports of the same day (yutraffic, panoscribe, penumbra, open-brain, MM-Agent), the outside reviewer's post-release notes, and this toolkit's own probes. Every finding below was **measured on a real consumer or in this repo** before it became an item; the line references are as of eef4277.

**Scope decision (user, 2026-09-23):** full patch — both hotfixes, both design decisions, the small checks and wording — and NOT the 10-of-36 plan-banner sweep, which is docs-only and rides any later release.

## §0 Principles this release adds to v4.1.1's five

- **A segmenter must see the command the shell sees.** A `\`+newline is ONE shell line — POSIX DELETES the pair. A splitter that cuts there judges fragments the shell never runs; in a fail-open hook that is a false deny, in a fail-closed guard it is a hole. And the normalisation must be applied ONCE, to the one string every reader shares: a pre-filter and a walk that read different text is v4.0.3 item 12 again (reviewer, round 1, measured on the merge gate's fast exit). (§1)
- **Two normalisations that are each correct alone can compose into a hole in one order.** bash does NOT continue a line inside a comment (`# note \`⏎`git push origin main` runs the push as its own command — reviewer, round 2, measured), so #8's whole-line comment strip must run BEFORE §1's continuation join: join-then-strip merges the push into the comment and deletes it. The order is stated in §1 and §4, pinned by one fixture, and never left to placement alone.
- **A check must tell the thing from prose about the thing.** A substring test for a retired name fires on the consumer who documented the retirement and stays silent for the one who did not. Key on the sentence that carries the harm, not on the token. (§2; the same class as the placeholder sweep firing on the toolkit's own docs and `deny-secret-reads` blocking a grep for its own pattern.)
- **"Absent because there is none" is not "cannot determine".** A contributor that is structurally unavailable on a legitimate layout must be redefined so it measures something on that layout, or the extension it gates is a dead letter there. Polarity (absent voids) stays. (§3)
- **A key nothing reads is convention, and the doc must say so.** (§4)

## §1 Hotfix — backslash continuations (#7 and its fail-closed twin)

### Measured
- yutraffic, during its v4.1.1 sync: `git add -- hooks/lib/git-cmd.sh hooks/gate-before-merge.sh hooks/run-gate.sh …` wrapped across backslash-continued lines → `enforce-delegation.sh` DENY "DELEGATE: builds/tests run inside agents". Reproduced at eef4277 with two fixtures through the hook: the ONE-line form → allowed (rc 0, no output); the continued form → deny.
- Root cause, `hooks/enforce-delegation.sh:201-204`: `cmd.split(/&&|\|\||[;&|\n]/)` — the continued line starting with `hooks/run-gate.sh` becomes its own segment; the v2.2.1 anchored matcher (`:197`) fires because that segment's first token is the path and the `^(git|gh)` exemption (`:172`) sees no `git`. The skill's step 9 (SKILL.md:1250) prescribes one line; the wrap was the model's, so it recurs whenever a long list is wrapped.
- Twin, `hooks/lib/git-cmd.sh:415-417` `gc_segments`: `printf '%s\n' "$GC_CMD" | tr -d "\"'" | tr '|;' '\n\n' | sed 's/&&/\n/g'` — newlines pass through as segment boundaries and nothing joins `\`+newline first. **Hypothesis, to be fixtured before it is claimed:** `git push \`⏎`  origin main` → segments `git push \` and `origin main`; `no-push-main.sh` then applies its no-refspec rule (current branch) to a push whose real target is `main`. On a feature branch that is a fail-OPEN.

### Measured by the reviewer (round 1) — the placement is the finding
- The merge gate's fast exit (`gate-before-merge.sh:738-743`) greps `$GC_CMD` LINE BY LINE before any segmenter runs: `gh pr merge 123` → the walk runs; `gh pr \`⏎`merge 123` and `gh \`⏎`pr merge 123` → **fast-exit 0, the merge gate never runs.** `grep` is line-oriented, `gh[[:space:]]+pr[[:space:]]+merge` cannot match across the pair, the `git` arm finds no token, and both greps failing takes the `exit 0`. A join inside the segmenters does not reach this. Both guards reassign `GC_CMD="$(gc_augmented_cmd "$CWD")"` before that grep (`no-push-main.sh:56`, `gate-before-merge.sh:706`), so the one place every reader inherits is that function's OUTPUT.
- What the shell does with the pair, byte-exact probes (od-verified): unquoted mid-word `pu\`⏎`sh` → executes `push` (pair DELETED, not spaced); `"a\`⏎`b"` → `ab` (continued inside double quotes); `'a\`⏎`b'` → literal, not continued; `bash -c '…push \`⏎`origin main'` → the INNER shell continues it; `a\\`⏎ (even backslashes) → `a\` then a NEW command on the next line.

### Census of command-text readers at f602f28 (reviewer, round 2 — every hook followed to where it reads)
- `gate-before-merge.sh`, `no-push-main.sh` — assign `GC_CMD` from `gc_augmented_cmd` before their grep: covered by the placement below.
- `pre-commit-test.sh` — SAFE: its only pre-augmentation read is `[ -n "$GC_CMD" ]` (`:234`), an emptiness test no continuation can affect; augmentation `:243`, segments `:248`, no text pre-filter.
- `enforce-delegation.sh` — the JS side, its own definition below.
- `require-skills-block.sh` — NOT a reader (guards Agent, reads `tool_input.prompt`; its `.command` hit is a comment). Listed so the census shows it was checked.
- **`deny-secret-reads.sh` — reads `tool_input.command` DIRECTLY (`:169`), tokenises with `tr … | tr -s '[:space:]' '\n'` (`:174`), sources `git-cmd.sh` nowhere (verified: zero references). The continuation's LF is a token boundary and the backslash is never removed. Measured with byte-exact payloads: `cat .env` → exit 2 BLOCKED (control); `cat .e\`⏎`nv` → exit 0 ALLOWED (bash runs `cat .env`); `ca\`⏎`t .env` → ALLOWED; `cat .env.lo\`⏎`cal` → ALLOWED.** The secrets guard has the identical fail-open, on reads of `.env` into the transcript, outside the one place a join in `gc_augmented_cmd` reaches.

### Change
- **One DEFINITION: `gc_join_continuations` in `hooks/lib/git-cmd.sh`** (stdin → stdout; deletes `\`+optional `\r`+`\n` when the backslash run before it is ODD). Applied at exactly two shell call sites: (a) inside `gc_augmented_cmd`'s output (`:541`) — the invocation text and any appended script body alike — so the pre-filter, the walk, `gc_segments` and `gc_seg_quoted` all read identical text and the quoted-flag list stays aligned for free; (b) in `deny-secret-reads.sh`, which now sources `lib/git-cmd.sh` (or the function is moved to `lib/json.sh`'s sibling scope, whichever the implementer measures as the lighter source — it must not pull the git subprocess helpers into a hook that never runs git) and applies it to `DSR_CMD` before its `tr`. Plus the SEPARATE JS definition in `enforce-delegation.sh` (after `stripHeredocs`, before `.split`), which shares no code with the shell library.
- **Order with #8's comment strip is load-bearing and stated here:** `gc_script_body` strips whole-line comments from a BODY first; the join runs afterwards on `gc_augmented_cmd`'s assembled output. Strip-then-join matches bash; join-then-strip is the hole in §0.
- **PowerShell branch, open question for a fixture, not a claim:** `deny-secret-reads.sh` and the git guards match `Bash|PowerShell`; PowerShell's continuation character is the BACKTICK. Whether a backtick continuation can split a token the way bash's `\` can is NOT established; the plan carries a fixture (`ca`⏎`t .env` under `tool_name: PowerShell`) whose verdict is recorded either way, and the join stays backslash-only until that fixture says otherwise.
- **Join to EMPTY, not to a space.** Join-to-space turns `git pu\`⏎`sh origin main` into `git pu sh origin main` — verb `pu`, unrecognised — while the shell runs `git push origin main`: a fail-open evasion built into the normalisation itself.
- **Delete the pair only when the backslash run before the newline is ODD.** `\\`⏎ is an escaped backslash followed by a real command boundary; a naive delete-every-pair merges two commands.
- **Match `\`, optional `\r`, `\n`** — Windows command strings can carry CRLF.
- Quoted wrapper payloads need nothing extra: double-quoted payloads are continued by the outer shell, single-quoted ones by the inner `bash -c`; joining a single-quoted literal that is never executed (an echo argument) is text, not a command — conservative in the gate's direction. The quote-strip that follows in `gc_segments` then sees already-joined text.
- Heredoc bodies are stripped first in the JS hook (v2.3.0); the join runs on what remains.

### Fixtures (scripts/test-hooks.sh; every fixture file written byte-exact and od-verified in the suite, since nested printf escaping wrote the wrong bytes on the reviewer's first probe)
1. enforce-delegation (JS side, yutraffic's false deny): the one-line `git add … hooks/run-gate.sh` → ALLOW (regression guard); the same continued → ALLOW (the fix); `bash \`⏎`hooks/run-gate.sh` → DENY (the joined segment starts with `bash hooks/run-gate.sh`; the join must not open the matcher).
2. gate-before-merge pre-filter (shell side, the reviewer's witness): `gh pr \`⏎`merge 123` and `gh \`⏎`pr merge 123` → gated (the walk runs; DENY without an artifact); `git pu\`⏎`sh origin main` → DENY (join-to-empty; a join-to-space would ALLOW this).
3. no-push-main: `git push \`⏎`origin main` from a FEATURE branch → DENY (the twin, closed); `git push \`⏎`origin feature` → ALLOW; `git push \`⏎`origin main` with CRLF → DENY.
4. pre-commit-test: `git commit \`⏎`-m x` → the test runs.
5. Escaped backslash: `printf 'a\\'`⏎`git push origin main` → DENY on the SECOND segment (the even-run pair is not joined); `printf 'a\\\'`⏎`git push origin main` (odd run) → joined — whichever detector then sees the merged text, the fixture records the verdict rather than reasoning about it.
6. gc_seg_quoted alignment: a continuation inside a quoted payload plus a second segment after `&&` → the flag list count equals the segment count.
7. Script body: a body appended by `gc_augmented_cmd` containing `git push \`⏎`origin main` → DENY (the join covers appended bodies because it lives in that function's output).
8. deny-secret-reads: the reviewer's three rows (`cat .e\`⏎`nv`, `ca\`⏎`t .env`, `cat .env.lo\`⏎`cal`) → DENIED, with `cat .env` as the control; and the PowerShell backtick row, verdict recorded.
9. Order: a body `# note \`⏎`git push origin main` → GATED (strip-then-join); the same body with the join applied first is the negative control the fixture documents, not runs.

## §3 Design — interpreter-prefix fingerprint (#11)

### Measured
- penumbra, artifact minted at v4.1.1: `pyvenv=absent|dist=15ebfe62…|py=Python 3.14.2|node=v24.12.0` — three contributors determinable, one structurally unavailable (system interpreter, no in-repo venv, an ordinary layout). `gate-before-merge.sh:1451/1486/1520`: `pyvenv` is one of four fixed contributors and ANY `=absent` voids the tree+env extension. So that repo can NEVER earn the 24 h extension; measured cost the same day: PR #172 sat 1 h 46 m between gate and merge, tree and environment identical, re-gate 61 s + an ops spawn — the second re-gate on that repo from this cause; item 13 (v4.0.3) was written for it, its measurement produced #15, #15's fix handed it back.
- `hooks/lib/git-cmd.sh:1009-1022`: `pyvenv_h` = sha256 of `server/.venv/pyvenv.cfg` when present, else the literal `absent`; the interpreter is then chosen (venv python, or `python3`/`python` on PATH).

### Change (user decision 2026-09-23: keep the label)
- `pyvenv` is redefined as **interpreter-prefix identity**: when `pyvenv.cfg` exists, its sha256 exactly as today (bytes unchanged for every venv repo → every existing venv-repo artifact stays valid); otherwise, when an interpreter resolves, the value **`sys:<sha256 of that interpreter's sys.prefix>`** (one `-c 'import sys; print(sys.prefix)'`, the SAME `$py_exe` that `dist` and `py` use) — the new shape's value is SELF-DESCRIBING by its prefix (reviewer, round 1): the system case was `absent` before, so it has no continuity to preserve and the prefix is free, and anyone debugging an invalidated artifact by hashing `pyvenv.cfg` themselves is never handed an unexplainable mismatch; `absent` only when NO interpreter resolves.
- **The void RULE is unchanged; no-venv repos become ELIGIBLE** — stated that way, never as "polarity untouched": any-absent still voids, but it now fires less often, because every no-venv repo moves from `pyvenv=absent` (always voided) to a value. For those repos the extension rests on `dist` for package changes, which #15 made discriminating. `a13_first_absent_label` and the void rule are not touched.
- **The absent-claim is ONE-DIRECTIONAL:** `pyvenv=absent ⇒ dist=absent ∧ py=absent` holds; the converse does not — a present-but-broken venv (`pyvenv.cfg` present, interpreter missing, the v4.1.1 #15 case) reads `pyvenv=<hash>|dist=absent|py=absent` and the void fires via `dist`/`py`. Written as an equivalence, a later "simplification" that derives `pyvenv` from the interpreter loses that case; the comment says so.
- The comment block at `:955-994` states the two shapes and why the label is kept (the rename to `prefix` was considered and rejected: a one-time invalidation of every consumer's artifact for no safety gain). CHANGELOG states the eligibility sentence for consumers, plus penumbra's datum: the widened `py` surfaced a real 3.14-vs-declared-3.12 mismatch — the widening earns its keep beyond invalidation.
- `run-gate.sh`'s standalone copy of `gc_gate_env` (the v4.1.1 Task 4 omission, caught then) changes identically; check 45-class byte-parity between the two copies is what proves it.

### Fixtures
- **Artifact continuity is pinned on the AGGREGATE, not the component** (reviewer, round 2: "bytes unchanged → artifacts stay valid" is a claim about the full fingerprint — four contributors, order, separators, final hash — and a refactor that keeps `pyvenv` byte-identical but perturbs the aggregation would invalidate every artifact while a component fixture stayed green): the suite computes the FULL fingerprint for a fixed venv fixture with the v4.1.1 `gc_gate_env` (read from `git show v4.1.1^{commit}:hooks/lib/git-cmd.sh`) and with the v4.1.2 one, and asserts equality; venv present: `pyvenv` component == sha256(pyvenv.cfg) as well; venv absent + interpreter on PATH: value == `sys:` + sha256(prefix) computed independently; no interpreter on PATH: `pyvenv=absent|dist=absent|py=absent` and the extension VOIDS (existing polarity fixture, re-run); present-but-broken venv: `pyvenv=<hash>|dist=absent|py=absent` and the extension VOIDS (the one-directional case, pinned); the extension GRANTS on a matching aggregate with all four present on the system-interpreter shape (new — the case the item exists for).
