# v4.1.2 — the v4.1.1 rollout patch (design)

**Status:** spec, branch `v4/1.2` (cut from `main` at eef4277 = tag v4.1.1). Written 2026-09-23 from the five consumer sync reports of the same day (yutraffic, panoscribe, penumbra, open-brain, MM-Agent), the outside reviewer's post-release notes, and this toolkit's own probes. Every finding below was **measured on a real consumer or in this repo** before it became an item; the line references are as of eef4277.

**Scope decision (user, 2026-09-23):** full patch — both hotfixes, both design decisions, the small checks and wording — and NOT the 10-of-36 plan-banner sweep, which is docs-only and rides any later release.

## §0 Principles this release adds to v4.1.1's five

- **A segmenter must see the command the shell sees.** A `\`+newline is ONE shell line. A splitter that cuts there judges fragments the shell never runs; in a fail-open hook that is a false deny, in a fail-closed guard it is a hole. (§1)
- **A check must tell the thing from prose about the thing.** A substring test for a retired name fires on the consumer who documented the retirement and stays silent for the one who did not. Key on the sentence that carries the harm, not on the token. (§2; the same class as the placeholder sweep firing on the toolkit's own docs and `deny-secret-reads` blocking a grep for its own pattern.)
- **"Absent because there is none" is not "cannot determine".** A contributor that is structurally unavailable on a legitimate layout must be redefined so it measures something on that layout, or the extension it gates is a dead letter there. Polarity (absent voids) stays. (§3)
- **A key nothing reads is convention, and the doc must say so.** (§4)

## §1 Hotfix — backslash continuations (#7 and its fail-closed twin)

### Measured
- yutraffic, during its v4.1.1 sync: `git add -- hooks/lib/git-cmd.sh hooks/gate-before-merge.sh hooks/run-gate.sh …` wrapped across backslash-continued lines → `enforce-delegation.sh` DENY "DELEGATE: builds/tests run inside agents". Reproduced at eef4277 with two fixtures through the hook: the ONE-line form → allowed (rc 0, no output); the continued form → deny.
- Root cause, `hooks/enforce-delegation.sh:201-204`: `cmd.split(/&&|\|\||[;&|\n]/)` — the continued line starting with `hooks/run-gate.sh` becomes its own segment; the v2.2.1 anchored matcher (`:197`) fires because that segment's first token is the path and the `^(git|gh)` exemption (`:172`) sees no `git`. The skill's step 9 (SKILL.md:1250) prescribes one line; the wrap was the model's, so it recurs whenever a long list is wrapped.
- Twin, `hooks/lib/git-cmd.sh:415-417` `gc_segments`: `printf '%s\n' "$GC_CMD" | tr -d "\"'" | tr '|;' '\n\n' | sed 's/&&/\n/g'` — newlines pass through as segment boundaries and nothing joins `\`+newline first. **Hypothesis, to be fixtured before it is claimed:** `git push \`⏎`  origin main` → segments `git push \` and `origin main`; `no-push-main.sh` then applies its no-refspec rule (current branch) to a push whose real target is `main`. On a feature branch that is a fail-OPEN.

### Change
- One normalisation, **join a backslash-newline pair to a single space**, applied BEFORE any split, in three places that must agree: the JS in `enforce-delegation.sh` (`cmd.replace(/\\\n/g, " ")` after `stripHeredocs`, before `.split`), and `gc_segments` AND `gc_seg_quoted` in `hooks/lib/git-cmd.sh` (they are a line-aligned pair — a join in one and not the other desynchronises the quoted-flag list; the header at `:419-437` says why they are separate functions). Mirrors under `user-level-reference/hooks/` byte-identical.
- Not a KNOWN_WRAPPERS-style enumeration: the join is the shell's own rule, one regex, no list to maintain.
- Heredoc bodies are stripped first in the JS hook (v2.3.0); the join runs on what remains, so a `\` at the end of a heredoc line is never seen.

### Fixtures (scripts/test-hooks.sh)
1. enforce-delegation: the yutraffic one-line `git add` → ALLOW (regression guard); the same continued → ALLOW (the fix); `bash \`⏎`  hooks/run-gate.sh` continued → DENY (the join must not open the matcher — the joined segment still starts with `bash hooks/run-gate.sh`).
2. no-push-main + gate-before-merge: `git push \`⏎`  origin main` from a FEATURE branch → DENY (the twin, closed); `git push \`⏎`  origin feature` → ALLOW.
3. pre-commit-test: `git commit \`⏎`  -m x` → the test runs (segment recognised as a commit).
4. gc_seg_quoted alignment: a command with a continuation inside a quoted payload and a second segment after `&&` → the flags list has the same count as the segments list. (Reviewer Q1 asked whether a continued line inside a quoted wrapper needs more than the join after quote-strip; the fixture answers it either way.)

### Cost if wrong
A join that is too eager (joining a literal `\\` + newline, i.e. an escaped backslash at line end) would merge two real commands into one segment; the regex `\\\n` matches exactly one backslash followed by newline — an escaped backslash is `\\\\` in the JSON and two characters in the command, and the second is not followed by newline. Fixture: `printf 'a\\'⏎`git push origin main` must still DENY on the second segment.

## §2 Hotfix — the seed arm keys on the sentence, not the token (#9), + the newest-first premise (#6)

### Measured

- `project_md_seed_differs` (the fact line) is untouched — it already reports the in-seed-annotation case as "differs" without a remedy by design (yutraffic's observation; a one-clause mention of "annotation inside the seed also reads differs" is added to its message text, no logic change).

## §3 Design — interpreter-prefix fingerprint (#11)

### Measured
- penumbra, artifact minted at v4.1.1: `pyvenv=absent|dist=15ebfe62…|py=Python 3.14.2|node=v24.12.0` — three contributors determinable, one structurally unavailable (system interpreter, no in-repo venv, an ordinary layout). `gate-before-merge.sh:1451/1486/1520`: `pyvenv` is one of four fixed contributors and ANY `=absent` voids the tree+env extension. So that repo can NEVER earn the 24 h extension; measured cost the same day: PR #172 sat 1 h 46 m between gate and merge, tree and environment identical, re-gate 61 s + an ops spawn — the second re-gate on that repo from this cause; item 13 (v4.0.3) was written for it, its measurement produced #15, #15's fix handed it back.
- `hooks/lib/git-cmd.sh:1009-1022`: `pyvenv_h` = sha256 of `server/.venv/pyvenv.cfg` when present, else the literal `absent`; the interpreter is then chosen (venv python, or `python3`/`python` on PATH).

### Change (user decision 2026-09-23: keep the label)
- `pyvenv` is redefined as **interpreter-prefix identity**: when `pyvenv.cfg` exists, its sha256 exactly as today (bytes unchanged for every venv repo → every existing venv-repo artifact stays valid); otherwise, when an interpreter resolves, the sha256 of the text `system:` + that interpreter's `sys.prefix` (one `-c 'import sys; print(sys.prefix)'`, the SAME `$py_exe` that `dist` and `py` use); `absent` only when NO interpreter resolves — and in that state `dist` and `py` read absent too, the genuine cannot-determine.
- Polarity unchanged: `a13_first_absent_label` and the void rule are not touched. The comment block at `:955-994` states the two shapes and why the label is kept (artifact continuity; the alternative rename to `prefix` was considered and rejected for a one-time invalidation of every consumer's artifact with no safety gain). CHANGELOG states the same in one sentence for consumers, plus penumbra's datum: the widened `py` surfaced a real 3.14-vs-declared-3.12 mismatch — the widening earns its keep beyond invalidation.
- `run-gate.sh`'s standalone copy of `gc_gate_env` (the v4.1.1 Task 4 omission, caught then) changes identically; check 45-class byte-parity between the two copies is what proves it.

### Fixtures
- venv present: value == sha256(pyvenv.cfg) (unchanged from v4.1.1's fixture value — a regression guard on artifact continuity); venv absent + interpreter on PATH: value != absent and == sha256("system:<prefix>") computed independently; no interpreter on PATH: `pyvenv=absent|dist=absent|py=absent` and the extension VOIDS (existing polarity fixture, re-run); the extension GRANTS on a matching aggregate with all four present on the system-interpreter shape (new — the case the item exists for).
