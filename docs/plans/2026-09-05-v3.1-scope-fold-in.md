# v3.1 scope — folding the v3.0.3/v3.0.4 backlog into the specs

**Status:** scope document for the consumer challenge round, 2026-09-05. Companion to
`2026-09-03-v3.1-ownership-model-spec.md` (the design), `2026-09-03-v3.1-template-diet.md`
(the prerequisite plan) and `2026-09-03-v3.1-gate-checked-branches-spec.md` (the candidate).
Source of the items: `docs/plans/2026-09-05-next-version-backlog.md` on `main` (merged as
`5d7bbb1`), every item measured by a consumer session against v3.0.3 or the v3.0.4 tip.

Three things this document does: (1) says, for every backlog item, whether the ownership
model **absorbs** it, whether it is **new v3.1 work** and in which repo, or whether it is
**deferred** with the reason; (2) records three places where the diet plan and the ownership
spec, both dated 2026-09-03, **contradict each other**, with the resolution; (3) lists the
questions the challenge round puts to each consumer.

## 1. Reconciliations between the two 2026-09-03 documents

**R1 — the diet plan diets a file the ownership spec stops shipping.** Diet Task 4 cuts
`CLAUDE.local.md` to ≤ 6 KB in all six variants. Ownership §3(a)/§5 removes it from the

**R2 — the diet plan's migration note describes the world the ownership spec abolishes.**
Diet Task 5 Step 1 says a sync will report CONFLICT on `CLAUDE.md` and consumers should
re-paste customs into the PROJECT-CUSTOM region. Ownership §7 replaces CONFLICT entirely and
§5 removes the region markers. *Resolution:* the diet ships in the same v3.1.0 as the
ownership model; the CHANGELOG migration note is ownership §11, and Task 5 Step 1 item (2)

removes them, `region.sh`, and the region checks in the same commit, so the consistency
script is never red between. Task 0 notes the ordering.

**R4 — repos line.** Ownership's header says the `sync-template` skill body lives in
`mcp-dev-servers`. It lives in this repo at `user-level-reference/skills/sync-template/`
(edited in v3.0.4); the server repo holds the MCP tools and the skill's *version contract*.
Corrected in the spec header.

**R5 — §10 "no hook or `hooks/lib/` change" no longer holds.** v3.1 carries the
`git-cmd.sh:937` fix (§3.1 below), which is in the lib. The parser matrix is therefore

"prefer a sibling function to avoid the matrix cost" argument no longer applies — the matrix

## 3. New v3.1 work, by repo

### 3.1 Toolkit — hooks and lib (parser matrix mandatory)

1. **`git-cmd.sh:937` `-C` fallback + class-3 on read-only verbs** (penumbra, yutraffic).
   Two refusals on `git -C <path> merge-base`: the unanchored `\bgit\b.*\b$2\b` fallback
   classifies `merge-base`, `--grep=merge`, `docs/merge.md` as the verb; and the class-3
   unresolvable-`-C` refusal fires before the verb is known. Both must go for §1b of the
   sync skill (`-C <templateRepo>` + descendant reasoning) to work as written. Fix shape:
   after `-C <operand>` and globals, match the verb as the first non-option token with arm
   1's anchor; resolve the subcommand first and refuse an unresolvable `-C` only for gated
   verbs. Fixtures: penumbra's four rows + want-2 controls (`git -C <path> merge feature`,
   `git -C <path> push origin main`), plus a third and fourth 0-control
   (`git -C <path> log -- docs/merge.md`, `git -C <path> merge-tree A B`); yutraffic's
   `git -C "$VAR" cat-file` → 0. Panoscribe ran five arms on protected main (A
   `merge-base --is-ancestor`, B same without `-C`, C `merge f/x`, D `merge-tree A B`, E
   `checkout feature/merge-fix`) — arm E is CONFOUNDED (branch-change logic at :834-837)
   and is not a control; only A-D count. **Warm-up branch `v3/v31-warmup`, in flight.**
2. **`last-precommit.json` overwritten by every Bash call** (MM-Agent): write the artifact
   only when a commit segment was found, or keep the last N rows; add a
   `matched-inside-quoted-word` note when the commit verb matched inside a quoted token
   (their 615 s false-positive Test run). `pre-commit-test.sh` only; no lib. Three
   consumers now (MM-Agent, yutraffic): yutraffic's post-commit read showed
   `no-commit-segment, rc -1, tree "", cmd_len 545` — their own inspection command
   overwrote the row. Inspecting the artifact is itself what destroys it.
3. **Commit gate keyed to the payload cwd, not an in-command `cd`** (controller, measured):
   document in the hook header and `docs/verification.md`; consider refusing a commit segment
   preceded by a `cd` clause, same shape as the mover-clause rule. Design question for the
   round: is refusal right, or is "gate the cwd the payload names, say so in the artifact"
   enough?
4. **Pipe-refusal wording blames the wrong clause** (penumbra 2): the discriminator calls
   `tail` an "earlier clause" when it is the pipe's later one, and a compound with a
   `checkout` in the same call should say "evaluated from `main` because the checkout is in
   the same call". Text only, in `gate-before-merge.sh` / `no-push-main.sh`. Penumbra's
   exact sentences: compound — "refused: <verb> evaluated on branch 'main' — the
   'git checkout -b <X>' earlier in this call has not run when this hook fires; split the
   call: checkout first, then <verb> alone."; pipe — replace "earlier clause" with "the
   pipe's later stage (`tail`) is not inert".
5. **`post-edit-build.sh`** (ownership §5a): new hook reading `**Post-edit build**:` from
   `PROJECT_CONTEXT.md`; `none` or placeholder → no-op; fixture in `test-hooks.sh`; no lib.
6. **Gate-checked branches** (companion spec, MM-Agent's requirements): rides v3.1 if its
   plan is ready; parser beside `gc_protected_branches` (R5).
7. **`**PO write surface**:` key** (penumbra F12): `hooks/enforce-delegation.sh` reads extra
   path prefixes from PROJECT_CONTEXT.md keyed `**PO write surface**:`; `none` = template
   default; `optional_absent` in the key audit; then the hook returns to `template`.
8. **SubagentStop matcher derived from the project's agents at runtime — REQUIRED**
   (MM-Agent): because `settings.json` is `template` class with no merge class, the v3.1
   hook derives the SubagentStop matcher from the PROJECT's `.claude/agents/*.md` at
   runtime (consumer-only agents included, e.g. their `mm-runner`/`finisher`), not a
   template-time list — otherwise MM-Agent's two project agents lose their contract hook on
   the first v3.1 sync.
9. **Tracked-only tree hashing** (penumbra F18) — moved here from §3.2 item 11: SHIP in
   v3.1, not a design pass. Would have prevented v3.0.3 item 8 (in-repo commit-message
   file) and the untracked-review-file case; would not prevent mutation-batched-with-commit
   (last-precommit.json's discriminator, already shipped). `add -A` never protected against
   a contaminating untracked file, it only forced a second run in the same tree. Shape:
   copy the real index (keeps staged new files), `git add -u`, `write-tree`. Three-arm
   fixture (`run-gate.sh`, no lib): untracked unignored file present → artifact tree ==
   `HEAD^{tree}` (match); unstaged edit to a tracked file → mismatch (control);
   `git add new.py` → gate → commit → match. Second reason (yutraffic): on a new branch's
   first commit the SHA arm can never match — PreToolUse runs before the commit exists
   (measured: `last-pass.json` sha = pre-commit HEAD, tree = the resulting `HEAD^{tree}`)
   — so the TREE arm is load-bearing, not optional polish, for this shape; reword the
   run-gate header when it ships to say so.
10. **`gate_self_reference` token normalisation** (open-brain RB1): tokens are compared
    after the same backtick/whitespace normalisation `run-gate.sh` applies to the field
    value — a backticked `**Gate**:` value is valid and must still match.
