## Part A — skills load on demand

### A0. Evidence

- **Size.** Skill text is 24,445 of the 29,075 B in a T1 coder spawn, which is 84% (BL §1).
- **Irrelevance at T1.** A T1 coder ("No new tests", `AGENT_TEAM.md:95`) still loads TDD (9,578 B) and receiving-code-review (6,203 B), although no review exists at T1 (BL §1, RV B2).
- **Double load.** karpathy is preloaded by the `skills:` frontmatter (`coder.md:9-10`), and the handbook requires it again (`AGENT_TEAM.md:312`). 137 of 333 coder transcripts invoked it anyway (BL §1). SD: "The full content of each listed skill is injected into the subagent's context at startup." SD also says this field "controls which skills are preloaded, not which skills the subagent can access: without it, the subagent can still discover and invoke … skills through the Skill tool". On-demand loading therefore needs nothing more than the `Skill` tool, which every agent carries; the consistency script's Skill-tool assertion is at `scripts/verify-template-consistency.sh:608-618`.
- **The enforcing hook.**
  - `hooks/require-skills-block.sh` checks only that the *heading* is present (`:192`), not that any skill ran.
  - It never fired from its creation (2026-04-12) until v3.0.0 (2026-09-02), because it read the fields at the wrong level (`:43-51`).
  - It has blocked **0 times in consumer transcripts**, against 2 lines in this repo's own development (BL §4, framed-message count).
  - The forced load did not produce compliance either: 79% of coder spawns carried the block, and only 57% invoked any skill (BL §1).
- **The check that blocked a simplification.** Check 8 (`verify-template-consistency.sh:115-122`) floors the `## Required Skills` heading count at ≥ 5. `docs/design-rationale.md:257-262` records that this floor stopped the two Lean Dev Prompt Templates from being merged into one.

Under U2 the hook is removed. Note what the evidence does and does not show: the count shows the hook *never fired* in a consumer. The hook was blind for most of its life, so the count cannot prove it never *would* have caught anything. The case for removal is low value plus high cost.

### A2. A karpathy digest inside the coder

- **What goes.** The coder files drop `skills: [karpathy-guidelines]` (`coder.md:9-10` and the same 2 lines in every coder).
- **The problem.** That preload is the only route by which the 11 "Toolkit working preferences" reach a coder (`user-level-reference/skills/karpathy-guidelines/SKILL.md:77-95`; check 20 floors them at 11). The digest must therefore carry the preferences, not only Karpathy's four principles.
- **Measured size:** 876 B. That is 9 bullets, a few lines more than "a few lines", deliberately. The section is byte-identical in all 12 coder files. It replaces `coder.md:36` (the root-cause bullet, 192 B), which it absorbs.

```markdown
## Working rules

- State your assumptions; if the brief allows two readings, say which you took and why.
- Smallest change that meets the brief: no unrequested features, abstractions or options.
- Touch only what the task needs and match the local style; mention unrelated dead code, do not delete it.
- Bugs: confirm the root cause from data (logs, a failing test) and fix it where the bad value starts.
- Tests check behaviour in general; never hard-code an expected value to make one pass.
- If an approach fails after a fair attempt, stop and rethink it instead of pushing on.
- Docs change with the code, in the same commit; a commit message says why.
- After a rebase or conflict, rebuild and rerun the tests; look for dropped imports and reverted lines.
- Commit intermediate work on long tasks. Finish clean: merged, worktree and temp files gone, leftovers reported.
```

**Preferences deliberately not carried:**
- "Implement, don't suggest" is about the PO.
- "Learn from corrections → Open Brain" cannot apply, because "Spawned agents cannot access Open Brain directly" (`AGENT_TEAM.md:349`).
- Every other preference maps to a bullet above.

**The skill file stays.** It is a user-level skill that the main thread uses. Only its preamble (`SKILL.md:79`, "All 12 coder agents preload this skill") is reworded to "The coder agents carry a digest of this section (`## Working rules`)". Check 20 stays unchanged.

### A3. `hooks/require-skills-block.sh` is removed, through a one-release stub

- **Why not delete it now.** Its registration is wrapped so that it fails closed (`settings.json:99`: exit 127 → "HOOK SCRIPT MISSING … exit 2"). ## Part B — the coder report becomes a short checklist

### B0. Evidence

- **Report size.** Coder final reports average 3,822 B (n = 332). `## Spec Compliance` averages 2,328 B (61%); `## Gate Results` averages 1,106 B (27.0%; 44% at WebSiteVerifier) (BL §5).
- **The pasted tail duplicates a machine check.** `gate-before-merge.sh` already verifies the SHA- and tree-matched artifact (`AGENT_TEAM.md:212-216`, RV (a\*)).
- **The hook has caused a proof loop.** One run reported four times, and an agent ran a 10-minute gate, including a deploy, on a zero-diff task to satisfy the contract (RV, `round6:29`).
- **How much it fires.** The hook prodded coders 305 times, in 241 transcript files. 51% of coder runs were prodded at least once (BL §4).
- **What the fires are.** These counts are **fires, not catches.** Plain `coder` was prodded 9 of 115 times, `dotnet-coder` 108 of 139 (BL §4). That spread looks like format nagging, not caught failures. Under U2 the hook is kept because it fires and its target is real (a missing report), but its form is made lighter, and S7 measures whether the lighter form stops the nagging.
- **What stays.** The per-item echo is the one mechanism that carries street-level detail up to the PO who approves (RV V12). The checklist keeps it, one line per item.

### B1. The short format (replaces `coder.md:46-62` in all 12 coder files)

```markdown
## Report (HARD REQUIREMENT)

End with this short report. A SubagentStop hook checks it. Do not paste test or gate output, and never re-run the gate only to report.

    - [pass] 1. <brief item>
    - [fail] 2. <brief item> — <why>
    - [n/a] 3. <brief item> — <why>
    Commit: <sha> | none — <why>
    Gate: <the GATE PASS line run-gate.sh printed> | none — <why>
    PR: <url> | none
    Concerns: none | <one line each>

One line per numbered item of the brief, in order; an item you did not do is `fail`, never omitted.

**Merging:** run `bash hooks/run-gate.sh` immediately before the merge call (the artifact must match the rebased HEAD; it expires after 60 min) and commit exactly what was gated.
```

(694 B, measured.) Notes on the format:
- **Merge mechanics are kept.** The two merge-mechanics rules from `coder.md:54-55` stay as the **Merging** line. They are operational, and losing them is the "lost detail" risk made concrete.
- **Zero-diff task:** `Commit: none — <why>` with `Gate: none — no change`. This is a complete report, so the round-6 zero-diff loop cannot recur.
- **Gate unset:** `Gate: none — Gate unset; commit-hook Test passed`. The commit hook's pass record `<common git dir>/gate/last-precommit.<tree>.json` is the evidence, and the report does not repeat it. This replaces today's "paste the Build/Test/Format/Lint tails" arm (`coder.md:56`), which was the remaining reason to paste.
- **The `GATE PASS` line** is the single line `run-gate.sh` prints, for example `GATE PASS <sha>` or, from v4.3.0, `GATE PASS <sha> (Test legs reused from <record>)`. It is a pointer, not output.
- **What is dropped:** "name the skills you invoked" (`coder.md:50`). It is evidence of evidence (RV B6).

### B2. What `hooks/enforce-agent-contract.sh` checks

The coder arm (`:141-150`; every `pipeline: true` type except `code-reviewer`) reads the final assistant text. The current extraction at `:107-127` is unchanged. A report is **compliant** if it is in either the SHORT form or the LEGACY form:

**SHORT form:** all four of the following, each an ERE matched case-insensitively per line. The patterns tolerate list markers, `**bold**` keys and backticks, which is the lesson from the gate field greps:
1. at least one checklist line: `^[[:space:]]*[-*][[:space:]]+\[(pass|fail|n/a)\][[:space:]]+[^[:space:]]`;
2. a commit line: `^[[:space:]]*(\*\*)?Commit(\*\*)?:(\*\*)?[[:space:]]*` followed by `` `?[0-9a-f]{7,40}`? `` or by `none`;
3. a gate line: `^[[:space:]]*(\*\*)?Gate(\*\*)?:(\*\*)?[[:space:]]*[^[:space:]]`;
4. a concerns line: `^[[:space:]]*(\*\*)?Concerns(\*\*)?:(\*\*)?[[:space:]]*[^[:space:]]`.

**LEGACY form:** both `## Gate Results` and `## Spec Compliance` (today's test, `:143-144`).
- It is accepted **without a prod** through v4.x.
- The reason is consumer-owned `pipeline: true` agents such as Motorsport-Manager's `mm-runner` (109 runs, BL caveats). They fall to the same `*)` arm, and their definitions are project-owned and never synced.
- LEGACY acceptance is removed at v5.0, with a CHANGELOG migration line.

**What the hook does not check:**
- that the checklist covers every brief item, since the hook cannot see the brief reliably;
- the PR line;
- report length;
- whether the named gate record exists. `gate-before-merge.sh` owns that, and a second check of it would be the evidence-of-evidence pattern (RV V9).

**Unchanged:**
- the loop guard (one forced continuation per session+agent, a sticky marker, `:153-172`);
- fail-open on breakage;
- the reviewer arm (`:133-140`, `:174-175`);
- the `pipeline:` eligibility (`:72-89`);
- the registration (`settings.json` SubagentStop, unwrapped).

**The new prod message** (replaces `:177`). It must no longer tell the agent to run the gate:

> `CONTRACT VIOLATION: your final report is missing <the missing lines>. End with the short report: one '- [pass|fail|n/a] <n>. <item>' line per brief item, then 'Commit: <sha>|none — <why>', 'Gate: <GATE PASS line>|none — <why>', 'Concerns: none|<lines>'. Do not paste test or gate output and do not re-run the gate to report.`

**Fixtures** (`scripts/test-hooks.sh`, the `ctr` block at `:4725+`). Each is two-sided:
- **Pass (exit 0):**
  - the short form;
  - the short form with bold keys and backticked sha;
  - a zero-diff report (`Commit: none — …`);
  - the legacy form.
- **Prod (exit 2):** each one of the four short-form lines missing; a short form whose only checklist line is `[done]`; an empty text.
- **Loop guard:** the existing 3-stop sequence, re-run on the short form.
- **Message content:** the prod message contains no `run-gate`.

## Part F — process vs progress measurement

### F0. Why

V17 is the video's most transferable idea (RV R7). The toolkit's two largest wins came from measurements like this one: tests took 43% of agent time (`docs/plans/2026-09-28-agent-time-sinks-design.md:4`), and the 417-call runaway (`hooks/agent-budget-warn.sh:4-5`). The measurement is a **script, not a hook**, and it raises no alerts.

### F1. `scripts/measure-process.py`

- **Implementation:** python3, stdlib only. Streaming JSONL over about 3 GB of transcripts is not feasible in bash, and python3 is already a toolkit prerequisite (`server/install.sh`).
- **Not shipped to consumers.** No `templates/ownership.json` rule matches `scripts/`, so it is never synced. It runs from the toolkit checkout, against any project's transcripts.

```
python3 scripts/measure-process.py [--project <slug>[,<slug>...] | --all]
                                   [--since YYYY-MM-DD] [--until YYYY-MM-DD]
                                   [--json] [--self-test]
```

- **Input:**
  - `~/.claude/projects/<slug>/*/subagents/agent-*.jsonl` plus the sibling `.meta.json` (`agentType`);
  - the main-thread `~/.claude/projects/<slug>/*.jsonl`;
  - worktree slugs folded into their repository (the BL §4 method);
  - a transcript is in the window if its first timestamp is.
- **Read-only.** Run it on an otherwise idle machine, never beside a gate (`mem:feedback_single_gate_stalls_machine`).

### F2. Classification: each tool call (and each text-only assistant turn) goes to exactly one bucket

Rules are applied top to bottom; the first match wins.

| Bucket | Rule |
|---|---|
| **process:review** | Every call inside a transcript whose `agentType` is `code-reviewer` or `architect` |
| **process:test** | Every call inside a `tester` transcript |
| **process:rules** | `Skill` calls, sized by their `tool_result` bytes |
| **process:prod** | Every assistant turn and tool call after the first `CONTRACT VIOLATION` stop-hook feedback in that transcript (the forced re-report) |
| **process:report** | The final assistant text turn of a subagent |
| **process:gate** | `Bash`/`PowerShell` whose command contains `run-gate.sh`, or one of the project's declared `**Test**`/`**Gate**`/`**Gate extra**`/`**Build**` command strings (read from `<cwd>/PROJECT_CONTEXT.md`), or matches `\b(pytest\|dotnet (test\|build)\|npm (run )?test\|cargo (test\|build)\|mvn\|gradle\|go test\|jest\|vitest)\b\|scripts/(test\|verify)-` |
| **process:wait** | `Monitor`, `TaskOutput`, `BashOutput`, `TaskStop`, or a `Bash` whose command is only `sleep …` |
| **progress:commit** | A `Bash` with a `git commit` segment. Wall-clock above 10 s on a commit call is **re-assigned to process:gate**, because the commit itself is sub-second and the rest is the commit hook's Test. |
| **progress:edit** | `Edit`, `Write`, `MultiEdit`, `NotebookEdit` |
| **progress:deliver** | `git push`, `git rebase`/`pull`/`merge`, and the MCP tools `create_pull_request`/`merge_pull_request`/`update_pull_request` |
| **neutral:orient** | `Read`, `Grep`, `Glob`, `WebFetch`, `WebSearch`, `ToolSearch`, and every other `Bash` (`ls`, `git status`/`log`/`diff`, …) |
| **neutral:spawn** | `Agent` calls in the main thread. The spawned transcript is classified on its own. |
| **unclassified** | Anything else. It is **reported with its count and the top 10 tool names**, and it is never folded into another bucket. |

**Measures per bucket:**
- **context load (primary "tokens"):**
  - formula: Σ over the calls of (`tool_result` bytes × the number of later assistant turns in the same transcript), ÷ 4;
  - why it is primary: cache reads dominate cost, and a byte in context is paid on every later turn;
  - why `usage.input_tokens` is not used: it is a caching artifact (`research-playbooks/B-our-data.md:32`);
  - the spawn prompt counts as a `process:rules` load when it carries a `## Required Skills` block; otherwise it is `neutral:spawn`.
- **output tokens:** `usage.output_tokens` of the turn that issued the call, split evenly across that turn's `tool_use` blocks. The final turn's output tokens count as `process:report`.
- **wall-clock:** the `tool_result` timestamp − the `tool_use` timestamp, matched by `tool_use_id`. Gaps between a result and the next assistant turn are reported as a separate **model** line and kept out of both shares.

**Shares:**
- `process / (process + progress)` per measure. This is the headline.
- Each bucket as a share of the total.
- The main thread is reported in a separate table.

### F3. Extra tables, so that S1-S7 come from the same tool

| Table | Contents |
|---|---|
| `spawn` | Per agent type: mean spawn prompt bytes and mean Skill bytes loaded, plus the agent-file and preloaded-skill bytes measured statically with `wc -c`, as BL §1 does |
| `report` | Coder-type final reports: mean, median, and the share of `## Gate Results` bytes, using the m6.js method from BL §5 |
| `prod` | Coder runs with ≥ 1 contract prod, divided by coder runs |
