# v6.1 S4: measurements behind the size cap and the git-call cap

Measured through `hooks/dispatch.sh bash` unless noted. Linux = this repo's CI-like host; cloud = the headless cloud session; PC = the Windows controller.

## Step 1: before the change

Linux, benign shapes (no git calls), dispatch.sh end to end:

| size | time |
|---|---|
| 16 KB | 0.11 s |
| 64 KB | 0.15 s |
| 256 KB | 0.32 s |
| 1 MB | 0.99 s |

Cloud, deeper shapes:

| shape | 16 KB | 64 KB | 256 KB |
|---|---|---|---|
| (c) many `git push` segments | 45.0 s | 176.9 s | >300 s |
| (d) one `git -C "<quoted path of words>"` | 14.5 s | 144.3 s | >300 s |
| (e) one long commit message | 0.15 s | 0.23 s | 0.52 s (1 MB: 1.80 s) |

`gc_protect_c_paths` alone (old sed loop, Linux), a quoted `-C` argument of words: 1 KB 0.72 s, 2 KB 1.59 s, 4 KB 3.75 s, 8 KB 10.1 s, 16 KB 36.8 s. Quadratic: one sed spawn and a full rescan per blank.

Real commands over 30 days: largest 11365 B (PC Bash; Linux 4075 B). Most git/gh calls in one command: 21 (PC); Linux 10, p99.9 12.

Conclusion: a byte cap alone cannot bound the time (c and d are slow at 16 KB), so S4 also makes `-C` protection linear and caps the git/gh calls.

## Step 5: after the change

`gc_protect_c_paths` is one POSIX awk pass; `dispatch.sh` refuses a command over `CCTD_MAX_PAYLOAD=262144` bytes and one with more than `CCTD_MAX_GIT_CALLS=128` git/gh calls. Linux (mawk 1.3.4), `timeout 60` around each run, empty project dir:

| shape | 16 KB | 64 KB | 256 KB |
|---|---|---|---|
| (c) many `git push` segments | 0.06 s (refused, call cap) | 0.09 s (refused, call cap) | 0.23 s (refused, call cap) |
| (d) one `git -C "<words>"` | 0.15 s | 0.29 s | 0.22 s (refused, size cap: 262159 B) |
| (e) one long commit message | 0.16 s | 0.31 s | 0.25 s (refused, size cap: 262159 B) |

Just under the cap (248 KiB): (d) 0.89 s, (e) 0.90 s; (c) is refused at once (0.25 s). Every shape finishes under 15 s or is refused.

The cloud host was not re-timed in this session; the Linux figures above are the post-change evidence, and the pre-change cloud figures show the cost was in the quadratic sed loop and the per-segment guard cost that the two caps remove.
