# v6.1 S3: which shell runs a hook command string

Measured by the controller (Task 3, Steps 1-2).

## Linux (Claude Code 2.1.319, agent-host-1)

- Hook command strings run under `/bin/sh`, which is dash. `BASH` is unset there.
- Claude Code does NOT expand `${...}` in a hook command string. The parent cmdline shows the string literally.
- dash therefore expands `${BASH:-bash}` to `bash`, which resolves to `/usr/bin/bash`. `exec bash` behaves the same.

## Windows (PC, Git for Windows)

- Hook strings run via `"C:\Program Files\Git\usr\bin\bash.exe" -c "<string>"`. `BASH=/usr/bin/bash` there.
- `exec "${BASH:-bash}"` therefore resolves to the running Git bash. It cannot fall through to a WSL bash on a PowerShell-style PATH.
- MSYS `exec` leaves the `-c` bash as a parent process.

## Ruling (Step 2)

Proceed. On Linux the change is neutral; on Windows it removes the PATH lookup.
