# v5.2.0 Agent-Friction Bundle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the agent friction open-brain measured on 2026-10-17 (backlog #21), give `.gitattributes` a project section (#19), and document the plugin-scope upgrade detail (#20), in one minor release.

**Architecture:** Two hook changes (`hooks/deny-secret-reads.sh`, `hooks/run-gate.sh` via `bin/cct-gate`), one hook investigation (`agent-budget-warn`), a template change (the six variant `.gitattributes` files gain an empty PROJECT-CUSTOM region), and agent-facing wording. No server code change is expected: the region splitter matches the marker text as a substring in any file.

**Tech Stack:** bash hooks, `scripts/test-hooks.sh` fixtures, `scripts/verify-template-consistency.sh` checks, the template-sync server's pytest suite (`server/tests`).

**Spec:** the user's rulings of 2026-10-17, recorded in memory `project_v461_backlog.md` #19/#20/#21 and in this plan's Global Constraints. No separate spec document; rulings below are provisional where marked.

## Global Constraints

- KISS. The simplest correct change; for a guard, a strict refusal over modelling more behaviour.
- Secret-read exemption scope (USER 13:57, "narrow"): a basename that is exactly `.env.example`, or matches `^\.env\.[A-Za-z0-9_-]+\.example$` (compared lowercased, as today). Judged per path word, never per command. Every other `.env*` name stays denied.
- `cct-gate` takes at most one optional argument, a directory. It fails closed: a missing directory, or one not inside a git work tree, is refused with exit 2 and a message; it never falls back to the current directory.
- `.gitattributes` region markers are `#` comment lines: `# <!-- PROJECT-CUSTOM:BEGIN -->` and `# <!-- PROJECT-CUSTOM:END -->`, the last two lines of each variant's file, with nothing between them.
- All six variant `.gitattributes` stay byte-identical (edit `templates/general/` first, then `cp`). Every file LF.
- Agent wording for the harness isolation guard (backlog #21 items 1-2) is wording only. No hook change for it.
- Never print environment variable values in any test or brief.
- Version 5.2.0: `VERSION`, `.claude-plugin/plugin.json`, `server/src/template_sync/VERSION`, the sync-template SKILL marker, every `#v5.2.0` pin (check 77), a CHANGELOG section with a signed `Floor reviewed:` line, and a measured v5.2.0 column in `docs/architecture.md` *Context Budget*.

## Review Focus

1. `cat .env.local.example .env` (an example name plus a real secret in one command) must still be refused: the exemption is per word.
2. `.env.example.bak`, `.env..example`, `.env.local`, `.env.examples` and `.env.local.example.txt` must still be refused.
3. `cct-gate /path/that/does/not/exist` and `cct-gate /tmp` (not a work tree) must refuse, not gate the current directory.
4. A consumer whose `.gitattributes` carries a local line OUTSIDE any region (mm-agent today) keeps seeing LOCAL_EDITED until the line moves into the region; after the move, status is clean. The skill must say so.
5. `cct-gate` with no argument behaves exactly as today (same exit codes and artifact).
