# v4.1.1 — rollout patch: derive-not-construct migration, honest checks, hardened hooks, the probe that shipped

Status: spec, branch `v4/1.1` (cut from `main` 038f247 = tag v4.1.0). Authored 2026-09-21 from the five-consumer v4.1.0 rollout (open-brain, panoscribe, yutraffic, penumbra, MM-Agent) and the outside reviewer's findings; every item below has a measured origin, a settled shape, and a witness that can fail. The backlog was labelled "v4.0.4" in v4.1.0's CHANGELOG; this release retitles it (the next patch sits on 4.1) and corrects that label in its own entry, never by a post-tag commit on `main`.

**User rulings (2026-09-21):** ONE bundled release, hotfix-first order; ship on a `v4/1.1` branch whose spec and plan never touch `main` before the release PR (a post-tag commit on `main` flips every consumer to case 3 / null `template_version` until §1.4 lands). **Deadline:** the machine's next reboot is 2026-09-23 07:30; the live `bash server/install.sh` (venv launcher lock) and the five consumer syncs happen after it, so tag + propagation must be done before it.

## 0. Principles this release states (each one cost a finding)

- **A migration transforms entries; it does not rebuild them.** Baselines and annotations are both things it was not asked to touch (§1.1).
- **Cannot-determine refuses.** An `absent` fingerprint contributor voids an extension; an unavailable held commit refuses a grant-agent re-hash (§1.1, §4.4).
- **A claim about what a check does is written from the check, not from the ruling that motivated it; a PR body is a claim about a diff, written from `git show`; a review verdict carries a scope line.** Three artefact types, one lesson, three instances in one release (§7).
- **Two questions, two lines.** *Mine differs* and *mine is harmful* never share an answer (§2.1).
- **Harm-keyed arms need an arm per release that retires something a seed points at** — so the judgement lives in a release-task step, not in a detector (§7).

## 1. Server (`server/src/template_sync/`)

### 1.1 `migrate_v3_to_v4` — derive, do not construct (#17 ×3 symptoms, #20) — HOTFIX
Today the loop at `v3.py:2047-2067` holds `entry` and discards it: (a) it re-renders every template-owned entry from the checkout's CURRENT template and stores that hash for files it never writes (#17: held v4.0.3 content vs stored v4.1.0 hash → LOCAL_EDITED with `template_changed: false` on exactly the files the release changed, and step 2's model-bump rule stays silent on the one release that changes the enforcement layer); (b) when the template no longer ships the file (`deletedAcknowledged`), the recompute resolves to nothing and it stores `"hash": ""` (`:2062`), which `classes_and_hashes` then correctly FAILs with a remedy that cannot fix it (MM-Agent); (c) it rebuilds every `once` entry as bare `{"ownership": "once"}` (`:2064-2065`), silently dropping `reason` and any other consumer annotation, reported in no field (#20, panoscribe).

**Change:** for every entry the migration does not write, **carry `entry["hash"]` forward unchanged** and merge annotations through the existing `carry_unknown_file_keys(old_entry, new_entry)` (`v3.py:484`; policy at `:475-478`: unknown keys are consumer annotations, preserved and reported; drop only from the closed `SUPERSEDED_*` lists). `CLAUDE.md` stays special-cased (it IS written). **Grant agents are the only entries that need a new hash** (v3 stored = un-spliced; disk = held + tools edit): render the HELD template (`migration_base`, which the dry-run already resolves) and splice the grants on it; if the base is unavailable, **REFUSE** the migration for grant agents (loud, recoverable) rather than store an un-spliced baseline (silent, permanent TEMPLATE_UPDATED that never converges). The refusal population is "has grants AND base unavailable".

**The dry-run asserts its own invariant** beside the fix, not instead of it: for every entry the migration will NOT write, previewed hash == stored hash. False today on three real consumers (yutraffic's preview: 66f45cfd / 048a7245 / b0f03feb on a v4.0.3 disk); true by construction after; a preview-time tripwire for any future baseline rewrite, on the consumer's machine, before a write.

**Do not extend the fifth writer witness to unwritten entries** — it asserts manifest hash == sha256 of the ON-DISK spliced file, and for an unwritten entry the disk holds the consumer's held version; extending it would "prove" carry-forward wrong. A stale stored hash is PRESERVED, not silently repaired (a migration is not where a wrong baseline gets discovered). H2 is untouched: `tpl_raw` is the caller's argument; carry-forward renders nothing.

**Witnesses:** held ≠ HEAD in one unwritten file → TEMPLATE_UPDATED after migration; held == HEAD → IDENTICAL (so a blanket keep-old-hash cannot pass); a `deletedAcknowledged` entry keeps its hash and `classes_and_hashes` stays green; a `once` entry with `reason` keeps it and the report names it as carried; grant agent with base → IDENTICAL; grant agent without base → refused with nothing written; the dry-run invariant is RED against a fixture manifest whose held commit differs from HEAD and GREEN after.

### 1.2 Grants detector routes through the region split (#31)
R-D's detector classifies the WHOLE agent diff, so an agent carrying a `tools:` addition AND region content is `local_diff_kind: mixed`, skipped, `grants_plan` empty, `agent-grants.json` written as `{}` — MM-Agent's 16 + 22 project tools silently got no durable home, the exact risk grants exist to close. **Change:** route the detector through `_split_custom_region` (the split `region_status` already uses — two comparisons, one truth), then test whether the REMAINING diff is tools-only. No second stripper. **Fixture:** MM-Agent's hand-derived grants (Explore 16, architect 22, 0 removals): a mixed agent must yield exactly that plan; after writing the grants and re-applying source=template the agent reads IDENTICAL (MM-Agent measured: no diff at all).

### 1.3 `template_load_manifest`: an honest migration signal (#14, #16 in step 0)
`migration_required` is hard-coded `False` on the v3+ path (`mcp.py:903`): it answers ONLY the v2→v3 question and carries no v3→v4 information — on stale AND current servers (five data points; panoscribe's decisive pair: `false` beside `template_verify`'s `status_clean FAIL MIGRATION_REQUIRED` in one call). `registered_tools ∋ template_migrate_manifest` is necessary-not-sufficient (v4.0.x already registered it). **Change:** add `manifest_migration` = `{"from": <n>, "to": <m>, "required": bool}` computed against the CURRENT template's manifest version (v2→v3 and v3→v4 both); keep `migration_required` for one release with its meaning stated in the field's docstring ("v2→v3 only"), remove in v4.2. Step-0 text: `server_commit` == the toolkit checkout's `git rev-parse HEAD` (never `git rev-parse <tag>` — an annotated tag resolves to the TAG OBJECT b8d9454…, not 038f247; use `<tag>^{commit}`) is the ONLY currency check. **Witness:** a v3 manifest against a v4-capable template → `manifest_migration.required == true`; a v4 manifest → false; the old field's value unchanged.

### 1.4 Case 2 compares tracked paths only (#9)
A docs-only edit to `user-level-reference/README.md` on `main` (#145) flipped every consumer to case 3 (`template_version` null, `untagged_template_tree`) until the next tag, because `derive_template_version(repo, commit, tracked_paths)` (`v3.py:1489-1501`) — which already compares per path via `_tree_id` — is called by all three callers (`:1607` finalize, `:1849`, `:2027` migrate) with `rules.tracked_paths`, the ownership.json UNIVERSE (`v3.py:116`), which includes `user-level-reference/**` paths no consumer manifest holds. **Change:** the callers pass the CONSUMER's set — the template-side paths of this manifest's template-owned entries (what a sync can actually apply here) — so a commit touching only paths this consumer does not track keeps case 2 and the tag's version. **Witness:** fixture template repo at a tag plus one commit touching `user-level-reference/README.md` → a consumer with no such entry reads case 2 with the tag's `template_version`; plus one commit touching `templates/general/CLAUDE.md` → case 3; a consumer whose manifest DOES hold the first path → case 3 on the first commit (the set is per consumer, not a global exclusion).

## 3. Consistency script (`scripts/verify-template-consistency.sh`)

### 3.1 The sentinel guarantee has no undeclared-variant hole (#29) — HOTFIX
Check 37 (`:3266-3272`) is the only check that enumerates the six `templates/<v>/CLAUDE.md` paths INLINE; check 26 (`:1963-1979`) iterates the declared `$VARIANTS` (`:17`). ### 3.2 Floor check arm 2 + the signed judgement line (#13)
Check 42 (`:3491-3549`) fails only when `requires_skill` is ABOVE `VERSION`; a stale-low floor is invisible (measured: everything-but-the-floor moved → 420/0). NOT equality with VERSION — the floor lagged correctly at `>=v3.1.3` across six releases; it is a compatibility judgement, same shape as `MIN_SERVER_FOR_V3`. **Change:** arm 2 — `requires_skill` is non-decreasing since the previous release. **Instrument (reviewer, settled):** the previous release's NAME comes from the CHANGELOG's second `## v` heading (a deliberate statement living in the gated commit — never `git describe --tags --abbrev=0`, which answers "nearest reachable tag" and moves with reachability and with any non-release tag); `commit := git rev-parse "v${version}^{commit}"` (#16); `floor := git show "${commit}:templates/ownership.json"` → `requires_skill` (the authoritative copy, no prose parsing — never the previous entry's `Floor reviewed:` line, which is presence-checked and unvalidated); assert current floor >= that floor by `sort -V`. **When the tag does not resolve locally: SKIP, naming it ("previous release tag v4.1.0 not present locally — fetch tags"), do NOT fail** — arm 2 is a DETECTION (failing closed blocks the gate for a missing tag with no safety gain; an unfetched tag does not make a decrease likelier), the opposite polarity from #15's extension, which is a PERMISSION; state this in the check's comment so nobody "corrects" it. ## 4. Hooks (`hooks/`, mirrored where `HOOKS_NO_MIRROR` allows)

### 4.1 The command-prefix gap (#11) — first among the non-hotfix items, it is the silent one
The canonical `bash scripts/test-hooks.sh` is refused under the repo's own hooks; ruling from v4.0.4: the refusal STAYS (a real self-reference gap), the PREFIX gap closes first, and a named auditable allowance for the suite comes later. **Measured (reviewer):** the gap is narrower than "wrappers defeat the gate" and it is a contract with no implementer. `gc_script_body()` (`hooks/lib/git-cmd.sh:455-458`) does `set -- $seg` and ANCHORS on `$1` — `case "$1" in bash|sh|source|.) ;; *) return 0` — so `command bash x.sh`, `env X=1 bash x.sh`, `exec bash x.sh`, `nohup bash x.sh` never reach the 16 KB body reader; its own docstring states the precondition "wrappers already stripped" and nothing in the lib establishes it (`gc_segments()` `:416` quote-strips and splits only). The git detector is NOT affected: `:681-687` SCANS tokens until one IS `git`, so `command git push origin main` is caught today. The hole therefore needs BOTH a gated verb inside a script AND a wrapped invocation — exactly the shape the Task 2 implementer hit. **Fix shape: scan, do not add a wrapper list** (a `KNOWN_WRAPPERS` enumeration would miss `time`, `timeout`, `stdbuf`, `xargs -I{} bash`, and whatever arrives next): in the segment's LEADING RUN, skip tokens that are `VAR=value` or bare words, stop at the first `bash|sh|source|.`, and stop at the first token that looks like an operand (bounds the scan to the command's head — an unbounded scan would read `x.sh` out of `git commit -m "run bash x.sh"` after quote-stripping). **Witnesses (test-hooks.sh):** `command bash probe.sh`, `env A=1 bash probe.sh`, `exec bash probe.sh`, `nohup bash probe.sh` (body carrying `git push origin main`) each block exactly as the bare `bash probe.sh`; `git commit -m "run bash x.sh"` does NOT read `x.sh`; the bare forms unchanged; plus one fixture with a wrapper deliberately NOT anticipated (`timeout 5 bash probe.sh`) so the residual is documented, not assumed closed.

### 4.2 `deny-claude-md-writes.sh`: one path normaliser (#23) + basename pre-filter (#24) + the version-gate sentence (#32)
Measured bypasses, all exit 0 with the write landing: the MSYS `/x/...` form (never equals the folded `x:/` root), `./CLAUDE.md`, `docs/../CLAUDE.md`, `claude.md` (case-insensitive filesystem); and a relative path resolves against the repo ROOT rather than the payload `cwd`, so `cwd=<root>/docs` + `CLAUDE.md` denies `docs/CLAUDE.md`, out of scope per the hook's own header. **Change:** one normaliser applied to the payload path and the root alike — resolve relatives against `cwd`, fold `/x/` → `x:/`, collapse `.`/`..`, case-fold on Windows (`cygpath -m` where present) — then compare. **Fixtures:** each shape above DENIES; `docs/CLAUDE.md` from `cwd=<root>/docs` ALLOWS; trailing-dot / trailing-space forms if Windows accepts them. **#24:** ~634 ms per editing call today (four `python3` spawns before any filter, on every Edit/Write/MultiEdit/NotebookEdit; `enforce-delegation.sh` pays the same on the same matcher) — a basename pre-filter before any JSON parse (`*/CLAUDE.md|CLAUDE.md` else exit 0), same treatment for enforce-delegation where its decision allows; witness: a non-CLAUDE.md payload exits 0 with zero interpreter spawns (measure with the hook-timing script). **#32 (notes):** the hook is version-gated (`:143`) — a consumer probing it before migrating reads exit 0 as inert; and the harness validates `old_string` BEFORE PreToolUse, so an Edit whose old_string does not occur returns "String to replace not found" with no hook error — only an edit that would otherwise succeed tests the hook (MM-Agent's near-false-defect).

### 4.3 The gate's environment fingerprint (#15)
`gc_gate_env` (`hooks/lib/git-cmd.sh:918-953`) derives `pyvenv`, `dist`, `py` ONLY from `<repo>/server/.venv`; on a consumer with system Python and no in-repo venv all three read `absent` and `env` is the node version alone (penumbra: `pyvenv=absent|dist=absent|py=absent|node=v24.12.0` while its gate ran 881 pytest assertions), so item 13's 24 h tree+env acceptance cannot see a python-side change on exactly the repos whose gate is python. **Change:** widen `dist` — the ONLY contributor that moves on a dependency change — to the site-packages of whatever interpreter the gate runs (`python -c 'import site,json;print(json.dumps(sorted(site.getsitepackages())))'` or a `pip list --format=freeze` hash), never `py` alone (a version string that would grant the extension while `dist` stays absent — a regression wearing a fix). **Polarity: ANY contributor reading `absent` voids the extension** (sha-exact artifact only); names no language; a node-only consumer earns the extension back by adding contributors that do not read absent (node version + lockfile hash). `absent` stays honest in `env_detail`. **Fixtures:** same `python --version`, different installed packages → fingerprint MUST differ; present-but-broken venv (`pyvenv.cfg` readable, interpreter missing) → void; no `server/.venv` → computed `dist` or the extension refused.

5. The `Floor reviewed:` line, signed with a reason.
6. The release gate runs with tags fetched (`git fetch --tags` as its own call) so §3.2's SKIP never shows at the moment it matters.
