# v3.1 Toolkit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the toolkit half of v3.1 — declared file ownership enforced through a v3 manifest, the hook and setup fixes five consumers measured, and a sync skill rewritten against the server's §7 statuses — in five independently mergeable phases, each ending in a green gate.

**Architecture:** Ownership is a fact declared once in `templates/ownership.json` and read by both repos; the toolkit asserts every template file has a class (consistency check), `setup-project` writes the class into a v3 manifest, and the server (mcp-dev-servers 0.3.0, planned separately, executes first) enforces it. Hooks keep their one-grammar rule: every new per-project value is a `**Key**:` line in `PROJECT_CONTEXT.md` parsed with `GC_KEY_PRE`, never a settings.json edit. The sync skill stops merging and starts reporting.

**Tech Stack:** Bash (hooks, consistency script, setup-project.sh), PowerShell 5.1 (setup-project.ps1), node (JSON in hooks and checks, already the gate's primary parser), Markdown. `hooks/lib/git-cmd.sh` changes in Phase 2 → the parser matrix is mandatory before the v3.1.0 tag.

**Spec:** `docs/plans/2026-09-03-v3.1-ownership-model-spec.md` (design + server contract), `docs/plans/2026-09-03-v3.1-template-diet.md` (prerequisite plan — Phase 0 here, not repeated), `docs/plans/2026-09-03-v3.1-gate-checked-branches-spec.md`, `docs/plans/2026-09-05-v3.1-scope-fold-in.md` (§3 work items, §7 measured ledger). All on `docs/v31-specs`; the plan argues from them.

## Global Constraints

- Server floor: manifest `requires_server: ">=0.3.0"`; a toolkit v3.1.0 tag is not cut until mcp-dev-servers 0.3.0 is released (spec §9).
- Never `git add -A` / `git add .` / `git commit -a`; stage by explicit path. Never push `main`. Never create `.claude/git-guard-off`. Commit messages via `git commit -F <file outside the repo>`; edit in one call, commit in the next. Author markdown/scripts with Edit/Write, never a Bash heredoc (the live gates scan the whole command string).
- Every file LF. `AGENT_TEAM.md`, `.claude/settings.json`, `.claude/agents/*.md` (generic ones) and every `hooks/**` file stay **byte-identical across all six variants** — edit `templates/general/` first, `cp` to the other five. Root `hooks/**` mirrors `user-level-reference/hooks/**` byte-for-byte (check 21, both directions; `HOOKS_NO_MIRROR` = enforce-delegation, enforce-agent-contract, agent-budget-warn, require-skills-block).
- `bash scripts/verify-template-consistency.sh` green at every commit (the pre-commit hook runs it, 58–117 s). `bash hooks/run-gate.sh` in the FOREGROUND (timeout 600000) before any merge; quote its summary line (`test-hooks.sh: N passed, 0 failed, 0 skipped`) — the verdict is `passed == expected AND skipped == 0`, never `failed == 0`. Removing an offending string is a fix; excluding it is a standing exception.
- `scripts/test-hooks-parser-matrix.sh` (node / python3-only / jq-only, ~90 min) before the v3.1.0 tag; restricted runs must skip a non-zero in-band count.
- Field grammar: every new PROJECT_CONTEXT.md key is `- **Key**: value`, read with `GC_KEY_PRE` (`hooks/lib/git-cmd.sh:260`: `^(${GC_BOM})?[-*[:space:]]*`), `none` = opt-out, an unfilled `{{…}}` is REPORTED, never treated as absent silently (gate-checked spec req. 3). Field values may be backticked; strip surrounding backticks before use (run-gate.sh:104 precedent).
- Version contract: toolkit and server are independent semver related by a stated floor; the skill body marker `<!-- SYNC-TEMPLATE-SKILL-VERSION: vX.Y.Z -->` must equal `v$(head -1 VERSION)` (check 21c-2g); VERSION line 2 is the release summary.
- Delete-the-guard on every new check or fixture: show the mutation applies (the anchor is asserted), show the row goes red, restore. A check that cannot fail looks exactly like one that passed.
- Consumer verification before the tag (spec §8): five consumers, read-only, `template_migrate_manifest(dry_run=true)` on their live trees; verdicts cited against the sha they measured, transfer by tree equality of every path the verdict rests on (docs/verification.md identity rule).

- [ ] **Step 1: Write the matcher**

```js
#!/usr/bin/env node
// ownership-classify.mjs — first-match-wins over the rules in templates/ownership.json.
// Globs: PurePosixPath-style; `**` matches across `/`, `*` within a segment.
// Classifies TEMPLATE-tree relative paths only (spec §4/§6); never consumer files.
import { readFileSync } from "node:fs";
const [, , tablePath, ...paths] = process.argv;
const table = JSON.parse(readFileSync(tablePath, "utf8"));
function globToRe(g) {
  let re = "^";
  for (let i = 0; i < g.length; i++) {
    const c = g[i];
    if (c === "*" && g[i + 1] === "*") { re += ".*"; i++; if (g[i + 1] === "/") i++; }
    else if (c === "*") re += "[^/]*";
    else if (".+?^${}()|[]\\".includes(c)) re += "\\" + c;
    else re += c;
  }
  return new RegExp(re + "$");
}
const compiled = table.rules.map(r => ({ re: globToRe(r.pattern), r }));
for (const p of paths) {
  const hit = compiled.find(x => x.re.test(p));
  if (!hit) { console.log(`${p}\tUNCLASSIFIED\t-`); continue; }
  console.log(`${p}\t${hit.r.ownership}\t${hit.r.target ?? "-"}`);
}
```
