## Challenge amendments

Recorded at integration, each with who measured it. These are the deltas between what shipped and what the plan above originally said.

- **A1 — bypass-recipe removed (yutraffic).** The shipped remedy for a config-inspection false positive (`grep -c 'Read(\.env' settings.json`) does NOT point at "a script file, where the hook sees only `bash <path>`" — that sentence is itself an evasion recipe against `deny-secret-reads.sh` (the hook scans the Bash COMMAND STRING; a script file's contents are not that string). The remedy points at the Read tool instead, and a permanent suite row asserts the rejected phrasing never reappears.
- **A1 — the TEXT clause itself was FALSE, and was removed, then replaced with a MEASURED clause (integration + yutraffic).** The plan's own A1 text — *"this matched the command TEXT; a literal secrets filename in any argument is enough"* — does not hold against the shipped hook's source: the Bash arm is VERB-KEYED (`DSR_READER` gates the whole match), so `echo .env`, `ls -la .env` and `stat .env` are all 0. The clause was removed rather than shipped misstating the hook's own rule. A replacement was then measured, not guessed: a consumer reproduced `echo 'Read(.env*) deny rules' && grep -c x settings.json` denying while `echo .env` alone, `grep -c x settings.json` alone, `cat settings.json && echo hello`, and `ls -la && echo .env` all allow — confirming the verb check and the secret-shape check both scan the WHOLE tokenized command with no per-clause split, so a verb in one clause and a secrets-shaped token in another still fire together (deliberate: a wrapper cannot hide the read by splitting it across `&&`/`;`/`|`). Confirmed against the source before shipping the sentence. Two permanent suite rows pin both directions: the cross-clause deny and a negative control where a reader clause carries no secret token. The deny message no longer claims the matched operand was necessarily "read" (`open-brain`'s wording concern) — it names the matched token instead.
- **A2 — three-row flip set, strip not comment (open-brain).** The marker-fixture rows exercising the actual regression are the three that move from (marker=1, artifact=0) to (marker=0, artifact=1: minted on an unrun suite) when the pre-v3.0.3 greedy strip is restored — trailing-marker rows in either field-name style. The over-correction control (`; true`) is a distinct, permanent row and must never flip.
- **A3 — marker-in-value, zero hook change (panoscribe).** The fourth extractor (`pre-commit-test.sh`'s `GATE_CMD_RAW` fallback) is made observable through its effect — a marker file written only if the whole value runs — rather than a new artifact field or hook change; the row does not depend on the thing it tests.
- **A6 — name-presence, not byte identity, plus four project-model exceptions with stated reasons (panoscribe, open-brain).** The reverse-mirror direction (check 21a) asserts a same-named mirror EXISTS, not that it is byte-identical — a consumer's own project-owned `run-gate.sh` may legitimately differ from the user-level copy on purpose. `HOOKS_NO_MIRROR` holds exactly four entries (`enforce-delegation.sh`, `enforce-agent-contract.sh`, `agent-budget-warn.sh`, `require-skills-block.sh`), and membership is a claim about USEFULNESS at user level (no agent team, no delegation surface, no per-task budget, no "## Required Skills" spawn convention to check) — never a claim about what the hook reads. `retro-brief.sh` was found unmirrored although it is machine-scoped exactly like the already-mirrored `retro-ledger.sh`; mirrored in this release rather than allowlisted.
- **A6b — retro pair census (open-brain).** Check 21c-2g asserts the retro base-dir helper is byte-identical between `retro-ledger.sh` (writer) and `retro-brief.sh` (reader). The rationale is stated as: the two hooks are TWO HALVES OF ONE FEATURE, not two hooks that happen to touch the same directory — sharing a directory would not require a shared helper; sharing a write/read contract on the same file does. A divergence would make the brief silently read an empty file.
- **B1 — tag-or-descendant, record the TAG when the tracked tree is identical (MM-Agent, penumbra's user).** The sync's pre-step now records the nearest release TAG as `lastSynced` (not the checkout HEAD sha) when the drift from that tag is a docs-only descendant with a byte-identical tracked template tree — otherwise the manifest label answers "which checkout sha did the server see" instead of "which release am I on."
- **B3 — heading-anchored, backed by a real fixture (yutraffic).** Placement correctness (SKILL.md step 4) is defined as heading-anchored, not exact-line-anchored, because the anchor line itself differs between template (`{{GATE_COMMAND}}`) and project (a real value). Landed as a durable test fixture at `scripts/fixtures/b3-placement/` (real, sanitized three-way content) plus `scripts/check-b3-placement.sh`, wired into `verify-template-consistency.sh` as check 34 — asserted RED on the misplaced merge and GREEN on the correct splice, both arms checked on every run.
- **B6 — keep 7b, server never writes `lastSyncedVersion` (panoscribe).** Confirmed at `template_sync_mcp.py:1302-1310`: `template_finalize_sync` mutates only `lastSynced`, `version` and `files`. The client-written 7b version-label stamp stays as originally shipped; a manifest already showing the fields was stamped by a previous 7b, not by the server.
- **B8 — live-run hook-write rule (MM-Agent).** Hook-file writes during `/sync-template` are documented as unrunnable while a live process polls Bash/PowerShell: the broad-matcher `gate-before-merge.sh` stays lock-held and the atomic rename fails `WinError 5`, measured three times running.
- **Verification rule added at integration, not in the original plan (open-brain via controller, prompted by A2's own false-green catch).** A suite's verdict is `passed == expected_total AND skipped == 0`, never `failed == 0` — a skip is a non-measurement wearing a green costume. Recorded in `docs/verification.md`'s rules list and in the CHANGELOG. No mechanical expected-total assertion was added to the gate itself in this release (scope freeze); it is a v3.1 item.
