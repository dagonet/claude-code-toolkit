# v4.0 Server Move Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The template-sync MCP server ships from this repo at `server/` as package `template_sync`, with the same tool names and manifest contract, one `VERSION` for templates, skill and server, and every consumer needing exactly three actions: install, re-register, restart.

**Architecture:** The two modules and 17 test files are lifted verbatim from mcp-dev-servers at tag `v0.3.8` into a hatchling package under `server/`, renamed `template_sync` with imports rewritten and nothing else changed. `__version__` is read at import from a `VERSION` file shipped as package data and pinned byte-identical to the repo-root `VERSION` by a consistency check, with no fallback. Two new load-response fields (`server_commit`, `server_in_template_repo`) are added to the moved code and read by the skill. The 235 tests become a third gate command at merge time. The splice floor is not raised.

**Tech Stack:** Python ≥3.11, hatchling, `mcp[cli]`, pytest (existing suite); bash + PowerShell 5.1 for install and setup; the toolkit's existing consistency-check and hook-fixture harnesses.

**Spec:** `docs/plans/2026-09-12-v4.0-server-move.md` — the authority. Where this plan and the spec disagree, the spec wins, except where a task records a **Ruling** against spec text; rulings are listed in the ledger and amended into the spec on the same PR.

## Global Constraints

Copied from the spec; every task's requirements include these.

- Console script name **`mcp-template-sync-tools`**, MCP server name **`template-sync-tools`**, tool prefix **`mcp__template-sync-tools__*`** — all unchanged. Only the command path moves.
- Source of the moved code: mcp-dev-servers **tag `v0.3.8`**, read with `git -C G:/git/mcp-dev-servers show v0.3.8:<path>`. Nothing in the moved code changes except imports, and the two new fields in Tasks 4–5.
- `MIN_SERVER_FOR_V3` stays **`"0.3.2"`**. New bootstraps stamp `requires_server: ">=0.3.2"`. No manifest is raised.
- `requires_skill` stays **`">=v3.1.3"`**; `skill_version_floor` stays a capability; both floor fields stay.
- `server_version` is the bare **`X.Y.Z`** from `VERSION` line 1 — never the tag, never a suffix. `template_version` stamps `v` + the same line.
- `__version__` has **no fallback**: a missing package `VERSION` raises at import; the server does not start.
- **0.3.8 stays installable** everywhere it can be installed. Nothing in this plan touches mcp-dev-servers; its 0.4.0 is Task 13's coordination, authored there.
- Every PR — and every fix to a PR — is reviewed by the mcp-dev-servers session from outside: pinned checkout `G:/git/claude-code-toolkit`, branch + sha per PR, they run the suite, they do not author. Merge only at the reviewed sha.
- Every file LF. `git add` and `git commit` are separate tool calls; never `git add -A`; never push to `main`; gate green (`bash hooks/run-gate.sh`) before every PR; implementers do not merge.
- Windows + Git Bash is the primary platform. Paths cross namespaces (MSYS `/g/…` vs Windows `G:\…`); any comparison of two paths happens in Python with `pathlib`, never as strings in bash or markdown.

```python
# server/src/template_sync/__init__.py
"""template-sync-tools, shipped from claude-code-toolkit.

__version__ is read at import from the VERSION file shipped as package data —
NOT from the repo root, which is not beside the package in a non-editable
install — and there is deliberately NO fallback. A server that cannot state
its version must not answer template_load_manifest: a wrong server_version is
a machine-wide load outage at every consumer carrying a requires_server floor.
"""
from importlib import resources as _resources

VERSION_PATH = _resources.files(__name__) / "VERSION"

try:
    __version__ = VERSION_PATH.read_text(encoding="utf-8").splitlines()[0].strip()
except (FileNotFoundError, OSError) as exc:
    raise ImportError(
        f"template_sync cannot determine its version: {VERSION_PATH} is missing or "
        "unreadable. Refusing to start rather than report a wrong server_version."
    ) from exc

_parts = __version__.split(".")
if len(_parts) != 3 or not all(p.isdigit() for p in _parts):
    raise ImportError(
        f"template_sync VERSION is not bare X.Y.Z: {__version__!r}. "
        "parse_version at every consumer accepts exactly three dotted integers."
    )
```

```bash
# server/install.sh — create server/.venv and install the package EDITABLE.
# Editable, so a later `git pull` advances the server at the next restart
# without a reinstall; reinstalling into a running venv is the one measured way
# to break it (locked launcher executables, no shim mid-flight).

[ -n "$PY" ] || { echo "install.sh: no python3/python on PATH" >&2; exit 2; }

"$VPY" -m pip install --quiet -e "$HERE[dev]"
```

- [ ] **Step 1: Write the checks**

```bash
# ---------------------------------------------------------------------------
# Check 43 — VERSION line 1 is bare X.Y.Z (v4.0). The server reports it as
# server_version; parse_version at every consumer accepts EXACTLY three dotted
# integers. A `v` or a `-rc1` here makes requires_server_satisfied return False
# for every consumer carrying any floor, at template_load_manifest -- a
# machine-wide load outage from a version-string format choice. The `v` lives
# in the tag and the skill marker only.
# ---------------------------------------------------------------------------
note "Check 43: VERSION line 1 is bare X.Y.Z"
c43_v=$(head -1 VERSION | tr -d '\r\n')
case "$c43_v" in
  [0-9]*.[0-9]*.[0-9]*)
    if printf '%s' "$c43_v" | grep -qE '^[0-9]+\.[0-9]+\.[0-9]+$'; then
      ok "check 43: VERSION line 1 '$c43_v' is bare X.Y.Z"
    else
      ko "check 43: VERSION line 1 '$c43_v' is not bare X.Y.Z -- every consumer's template_load_manifest would refuse"
    fi ;;
  *) ko "check 43: VERSION line 1 '$c43_v' is not bare X.Y.Z -- every consumer's template_load_manifest would refuse" ;;
esac
# Control: a value that must fail the same test.
printf '%s' "v9.9.9" | grep -qE '^[0-9]+\.[0-9]+\.[0-9]+$' && ko "check 43 CONTROL: 'v9.9.9' passed the shape test -- the test is inert"

# ---------------------------------------------------------------------------
# Check 44 — the package VERSION is byte-identical to the repo-root VERSION
# (v4.0). Two sources, one check: __version__ is read from the package copy so
# non-editable installs work; the root is what tags and templates derive from.
# ---------------------------------------------------------------------------
note "Check 44: server/src/template_sync/VERSION is byte-identical to VERSION"
if [ ! -f server/src/template_sync/VERSION ]; then
  ko "check 44: server/src/template_sync/VERSION missing -- the server would refuse to start"
elif cmp -s VERSION server/src/template_sync/VERSION; then
  ok "check 44: package VERSION == root VERSION"
else
  ko "check 44: package VERSION differs from root VERSION -- server_version would disagree with template_version"
fi
```

```python
# After the move, templates are read from disk on every call and advance the

# makes a reader assume both match; mid-session they do not. Reporting the

SERVER_SOURCE_DIR = _server_source()
```

`mcp.py` has **two** path helpers, and only one is the resolver. `_normalize_path` (`:159-161` at v0.3.8) swaps backslashes for forward slashes and nothing else — feeding it `/g/git/claude-code-toolkit` and resolving yields `G:\g\git\claude-code-toolkit`, which does not exist, so the function would answer **False for a consumer who correctly re-registered**: the exact false negative this field exists to remove.
```python
def _server_in_template_repo(template_repo: str) -> bool:
    """True iff the running server's source is inside the manifest's templateRepo.

    Computed HERE, where the resolver lives, because the two values cross a
    namespace: templateRepo is written by setup-project.sh under Git Bash as
    /g/git/..., server_source is a pathlib string as G:\\git\\...; a string
    containment test in the skill reported "not re-registered" to a consumer
    who correctly had. The skill reads this boolean and never compares paths.
    """
    if not template_repo:
        return False
    try:
        repo = pathlib.Path(_resolve_path(template_repo)).resolve()   # _resolve_path, NOT _normalize_path
        src = pathlib.Path(SERVER_SOURCE_DIR).resolve()
    except (OSError, ValueError):
        return False
    if not repo.exists():
        return False
    try:
        src.relative_to(repo)
        return True
    except ValueError:
        return False
```
