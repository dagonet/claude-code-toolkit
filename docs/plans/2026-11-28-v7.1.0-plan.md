# v7.1.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A sync offers each `PROJECT_CONTEXT.md` line the template changed and the project still holds in its old form (B-18), and three cleanup items land with it (B-7, B-12, B-10).

**Architecture:** The sync server pairs old and new template lines strictly and reports the pairs whose old line stands exactly once in the project's file (`key_audit.line_offers`); finalize remembers the base commit of what stays open (`pending_once_lines`). The skill asks once and makes exact one-line edits. The cleanups are independent small changes.

**Tech Stack:** Python 3 (server, pytest in `server/tests`), bash (consistency script, hook suite), Markdown (skill, docs).

**Spec:** `docs/plans/2026-11-28-once-line-offers-design.md` (B-18, approved 2026-11-28). B-7, B-12 and B-10 have no spec; their task text is the requirement.

## Global Constraints

- KISS: the simplest correct change; a strict "no offer" beats modelling more cases.
- No file under `templates/` changes: v7.1.0 must not require a template sync.
- No new MCP tool, no new `template_verify` line, no change to the `once_notes_changed` line.
- Check 35 caps are only ever lowered: `user-level-reference/CLAUDE.md` stays at or below 7856 bytes.
- Every file is LF.
- Tests first: each new test or row is run red before the change and green after; the report says so.
- Commits: `git add` and `git commit` are separate commands; the message is written with the Write tool and passed with `git commit -F <file>`; no heredocs; never `--no-verify`; never push to `main`.
- Never print environment variable values.
- The gate (`hooks/run-gate.sh`) and the parser matrix are run by the controller, not by a task's implementer. An implementer runs `bash scripts/test-server.sh` and the named sections or checks only.

## Review Focus

1. A project file with CRLF line endings: the old line is still found (Task 1 test `test_line_offers_match_a_crlf_project_line`).
2. The old line stands twice in the project's file: no offer (Task 1 test `test_line_offers_need_the_old_line_exactly_once`).
3. The template changed the same line twice, with a skip between: the offer carries the newest text (Task 1 test `test_skipped_offer_returns_with_the_newest_text`).
4. The stored `from_commit` no longer resolves: no crash, the normal base is used (Task 1 test `test_pending_line_entry_with_a_lost_commit_falls_back`).
5. The new line holds an unfilled `{{...}}` token, or the old line holds regex characters: no offer for the first, an exact whole-line match for the second (Task 1 tests `test_line_offers_skip_a_placeholder_in_the_new_line`, `test_line_offers_compare_whole_lines_literally`).

**Interfaces:**
- Produces, in `v3.py`:
  - `line_pairs(tpl_at_base: str, tpl_now: str) -> list[tuple[str, str]]`: (old, new) lines without line endings, in file order.
  - `line_offers(tpl_at_base: str, tpl_now: str, proj_text: str) -> list[dict]`: `[{"old": str, "new": str}]`.
  - Status: `info["key_audit"]["line_offers"]` (list, possibly empty) and `info["key_audit"]["line_offers_base"]` (the ref the base text was read from), both present exactly when a base resolved, for a once-class file with `"audit": "keys"`.
  - Manifest and finalize response: `pending_once_lines: [{"file": str, "from_commit": str}]`, sorted by file; the key is absent from the manifest when the list is empty; the response always carries the list.
  - Capability name: `line_offers`.

**Rules (from the spec, binding):**
- Pairing: unified diff of base against now with `n=0`. In a hunk with removed and added lines: a removed `**Key**:` line and an added `**Key**:` line with the same key name (as `KEY_LINE_RE` reads it) are a pair; a hunk of exactly one removed and one added line is a pair whatever the lines are. Nothing else pairs.
- Offer: old != new; new holds no `{{...}}` (`PLACEHOLDER_RE`); old equals exactly one whole line of the project text, compared literally after removing a trailing `\r` and the line ending.
- Base: if `manifest["pending_once_lines"]` has an entry for the file and `resolve_base` on a manifest copy with `template_commit` = its `from_commit`, `lastSynced` = None, `template_version` = None returns text, that is the base and `line_offers_base` is that commit. Otherwise the base is the one already resolved for the audit and `line_offers_base` is its returned label.
- Finalize: from the status it already computes, `pending_once_lines` = one entry per once-class file with a non-empty `line_offers`, `from_commit` = that file's `line_offers_base`. A status error leaves the stored list untouched and appends `pending_once_lines not recomputed: <error>` to `warnings`.

```python
def test_line_pairs_single_changed_key_line():
    base = "- **Ollama**: see CLAUDE.local.md\n- **Gate**: g\n"
    now = "- **Ollama**: see the mcp-usage skill\n- **Gate**: g\n"
    assert v3.line_pairs(base, now) == [("- **Ollama**: see CLAUDE.local.md", "- **Ollama**: see the mcp-usage skill")]

def test_line_pairs_match_key_lines_by_name_in_a_multi_line_hunk():
    # two adjacent key lines change, and their order swaps in the template
    base = "- **A**: 1\n- **B**: 2\n"
    now = "- **B**: 20\n- **A**: 10\n"
    assert sorted(v3.line_pairs(base, now)) == [("- **A**: 1", "- **A**: 10"), ("- **B**: 2", "- **B**: 20")]

def test_line_pairs_one_to_one_hunk_pairs_any_lines():
    assert v3.line_pairs("x\nold note\ny\n", "x\nnew note\ny\n") == [("old note", "new note")]

def test_line_pairs_nothing_for_additions_deletions_and_unequal_non_key_hunks():
    assert v3.line_pairs("a\n", "a\nb\n") == []
    assert v3.line_pairs("a\nb\n", "a\n") == []
    assert v3.line_pairs("a\nb\nc\n", "a\nx\ny\nz\nc\n") == []

def test_line_offers_need_the_old_line_exactly_once():
    base, now = "- **K**: old\n", "- **K**: new\n"
    assert v3.line_offers(base, now, "- **K**: old\n") == [{"old": "- **K**: old", "new": "- **K**: new"}]
    assert v3.line_offers(base, now, "- **K**: mine\n") == []                  # customized
    assert v3.line_offers(base, now, "- **K**: old\n<!-- \n- **K**: old\n-->\n") == []   # twice

def test_line_offers_match_a_crlf_project_line():
    assert len(v3.line_offers("- **K**: old\n", "- **K**: new\n", "x\r\n- **K**: old\r\ny\r\n")) == 1

def test_line_offers_skip_a_placeholder_in_the_new_line():
    assert v3.line_offers("- **K**: old\n", "- **K**: {{X}}\n", "- **K**: old\n") == []

def test_line_offers_compare_whole_lines_literally():
    base, now = "- **K**: a.b (c)* `d`\n", "- **K**: new\n"
    assert v3.line_offers(base, now, "- **K**: aXb (c)* `d`\n") == []           # `.` is not a wildcard
    assert v3.line_offers(base, now, "pre - **K**: a.b (c)* `d`\n") == []        # not a whole line
    assert len(v3.line_offers(base, now, "- **K**: a.b (c)* `d`\n")) == 1
```
