# v6.0 Hook Dispatcher Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every Bash or PowerShell tool call starts one cct dispatcher process instead of six guard processes. Each guard decides exactly as it does today.

**Architecture:**
- `hooks/dispatch.sh <table>` reads the payload once, parses it once into a memo array, and runs each guard of its table in a fixed order.
- Each guard runs as a `( . guard.sh )` subshell, after the same class, polarity and step-aside decision that `run-hook.sh` makes today.
- The guards change in two mechanical ways only:
  - they find their libs without `dirname`;
  - they take the payload from the memo array when it is present.
- An exported environment variable cannot fill a bash array, so the array cannot be injected from outside.

**Tech Stack:** bash (Linux and Git Bash), the existing `hooks/lib/json.sh` (node → python3 → jq), `scripts/test-hooks.sh`, `scripts/verify-template-consistency.sh`.

**Spec:** `docs/plans/2026-11-01-v6.0-hook-dispatcher-design.md` (approved 2026-11-01 11:11, dashboard #171 A). Read it first. Sections are cited as D1-D6 and §5-§9.

**Refinement of D5(b), decided in this plan (Ruling P-1):**
- **The ruling.** The payload is handed over in the memo array `CCTD_MEMO` (index 1), not in a scalar plus a "was I sourced?" test.
- **Why it is safe.** Bash cannot import an array from the environment. An exported `CCTD_MEMO=x` can only fill index 0, so it can never supply a payload or a memo hit.
- **What it removes.** The sourced test inside libs, and its trap (`BASH_SOURCE[0]` there is the lib) disappears.
- **Cost if wrong:** one row in Task 3 goes red.

## Global Constraints

- **KISS.** No guard's decision logic changes. There is no substring prefilter: every guard in a table sees every call of that tool.
- **Exact registration strings** (D1). Matcher `Bash`: `f="${CLAUDE_PLUGIN_ROOT}/hooks/dispatch.sh"; [ -r "$f" ] || { echo "BLOCKED: cct plugin files are missing (the plugin was upgraded or removed while this session ran) -- restart this session." >&2; exit 2; }; exec bash "$f" bash`, with `"timeout": 3360`. Matcher `PowerShell`: the same string, ending in `powershell`.
- **Tables and order** (D2), exact:
  - `bash` = no-push-main, deny-secret-reads, gate-before-merge, pre-commit-test, deny-hang-shapes, enforce-delegation;
  - `powershell` = no-push-main, gate-before-merge, pre-commit-test.
- **Unchanged registrations:** `agent-budget-warn` stays its own no-matcher registration (D3). Agent, the merge-tool matcher, Read, Edit, SessionStart, PostToolUse, SubagentStop and SessionEnd are untouched.
- **Exit codes per guard** (D4):
  - rc 2 stops the run, and the dispatcher exits 2;
  - any other rc continues to the next guard;
  - stdout is printed only when the dispatcher exits 0;
  - two guards writing stdout gives exit 2;
  - a dispatcher error of its own gives exit 2.
- **Variables:** the dispatcher's own variables start with `cctd_` (internal) or `CCTD_` (handed to guards). It never uses `set -e` or `set -u`, and never exports anything.
- **The repo's own checks:**
  - The gate is three commands: `bash scripts/verify-template-consistency.sh`, `bash scripts/test-hooks.sh` and `bash scripts/test-server.sh`.
  - Run every suite in the foreground with a 600000 ms tool timeout.
  - The parser matrix (`scripts/test-hooks-parser-matrix.sh`) runs before the release, because `json.sh` changes.
- **Repo rules:**
  - Every file is LF.
  - Never push to main, never use `--no-verify`, never create `.claude/git-guard-off`.
  - Never print an environment variable's value; run hooks with `env -u TYPESAFE_API_KEY`.
  - No heredocs in Bash tool commands: write scripts with the Write tool and run `bash <file>`.
- **Downstream:** the release ships in the plugin only, with no `/cct:sync-template`. The template inline guard is v6.1 (§9).

## Review Focus

1. **Payload larger than a pipe buffer** (a 300 KB `git push origin main …` command). The dispatcher's builtin read and the memo hand it over intact, so the push is still denied. The test goes in Task 4.
2. **Payload with a UTF-8 BOM prefix.** `json_fields` strips the BOM before parsing. The memo must compare the BOM-stripped text, or every guard re-parses (slower) or, worse, answers differently. The test goes in Task 2.
3. **The toolkit repo itself.** It registers its own copies of pre-commit-test, no-push-main, gate-before-merge and deny-hang-shapes. Inside it, the dispatcher must skip exactly those and still run deny-secret-reads and enforce-delegation, as `run-hook.sh` does today. The test goes in Task 4.
4. **A commit whose **Test** prints to stdout.** Inside the dispatcher, a guard's stdout is captured. If pre-commit-test passes the Test's stdout through, the dispatcher would print it as the hook's answer (or trip the two-writers rule). The dispatcher's stdout must equal what pre-commit-test prints when run directly, today. The test goes in Task 4.
5. **A guard that `exit`s from inside a function or a trap.** The status must still be that guard's verdict and must not end the dispatcher. pre-commit-test's ceiling path exits from inside a function. The test goes in Task 4.

### Task 4: `hooks/dispatch.sh`

**Files:**
- Create: `hooks/dispatch.sh`
- Test: `scripts/test-hooks.sh` (a new `v6 dispatch` block)

**Interfaces:**
- Consumes: `hc_class` and `hc_skip` (Task 1), `json_memo_set` (Task 2), the guard edits (Task 3).
- Produces (functions in `dispatch.sh`; the main part runs only when `${BASH_SOURCE[0]} == "$0"`, so tests can source it):
  - **`cctd_prepare`** does the following, in order:
    - `unset CCTD_MEMO`;
    - reads stdin with `IFS= read -r -d ''`;
    - calls `json_memo_set "$payload" tool_name cwd tool_input.command tool_input.file_path`;
    - reads `$proj/.claude/settings.json` and `$HOME/.claude/settings.json` once each with the builtin read (`proj = ${CLAUDE_PROJECT_DIR:-.}`, as in `run-hook.sh`).
  - **`cctd_dir`** is the dispatcher's own directory, made absolute and POSIX the way `run-hook.sh` does it: `cctd_dir=$(cd "${BASH_SOURCE[0]%/*}" && pwd)`, falling back to `.` when the path has no `/`. That costs one subshell, and the main shell's current directory never changes, because the guards rely on it. Every guard is sourced by `"$cctd_dir/<name>.sh"`, so its `${BASH_SOURCE[0]%/*}` (Task 3) is that same clean path.
  - **`cctd_source_guard <name>`** is the runner with no selection. It runs `cctd_o=$( set --; . "$cctd_dir/<name>.sh" </dev/null )`, returns the guard's rc, and appends non-empty stdout to `cctd_outs` (an array). Task 6's replay calls it directly.
  - **`cctd_run_guard <name>`** is selection, then the runner. It calls `hc_class` and `hc_skip`, and applies the polarity of a missing file:
    - a skipped guard returns 0;
    - a missing closed guard prints `run-hook.sh`'s `HOOK SCRIPT MISSING` text and returns 2;
    - a missing warn guard prints the `WARN` text and returns 0.

    Otherwise it returns `cctd_source_guard <name>`.
  - **`cctd_main <table>`** handles the run:
    - an unknown table prints `HOOK BLOCKED: dispatch.sh: unknown table '<x>'` and exits 2, as does a missing or corrupt lib;
    - otherwise it calls `cctd_prepare`, then `cctd_run_guard` for each guard in table order;
    - the first rc 2 exits 2;
    - at the end, more than one stdout gives `BLOCKED: dispatch.sh: two guards answered on stdout -- cannot determine` and exit 2;
    - otherwise it prints the stdout and exits 0.

- [ ] **Step 1: Write the failing tests.** Rows `v6 dispatch: ...`. Each one runs `printf '%s' "$P" | bash "$ROOT/hooks/dispatch.sh" <table>` in a fixture project; where a stand-in guard is needed, it uses a scratch copy of `hooks/` under `$TMPROOT`.
  - **(a)** A push to main gives rc 2 with the no-push-main needle, on `bash` and on `powershell`.
  - **(b)** `cat .env` gives rc 2 on `bash` and rc 0 on `powershell`, which has no deny-secret-reads.
  - **(c)** `ls` gives rc 0 with empty stdout.
  - **(d)** In the scratch copy, deny-secret-reads is replaced by a stand-in that exits 1. A push to main still gives rc 2: a crash does not skip a later closed guard.
  - **(e)** The scratch no-push-main gets a syntax error: rc 2, and a marker written by the scratch gate-before-merge is absent, so later guards do not run.
  - **(f)** A stand-in prints `{"x":1}` and exits 0: the dispatcher prints it and exits 0. Two stand-ins print: rc 2 with the "two guards answered" needle. A stand-in prints and a later guard denies: rc 2 with empty stdout.
  - **(g)** A stand-in that does `trap '[ "$?" = 127 ] && exit 2' EXIT; nonexistent_cmd_xyz` gives rc 2.
  - **(h)** A missing scratch `deny-hang-shapes.sh` (open) gives rc 0. A missing `no-push-main.sh` (closed) gives rc 2 with `HOOK SCRIPT MISSING`.
  - **(i)** Step-aside: a fixture project whose `.claude/settings.json` registers its own `hooks/no-push-main.sh` (file present) makes the dispatcher skip no-push-main. A marker stand-in proves it did not run, while deny-secret-reads still denies `cat .env`.
  - **(j)** No dispatcher argument reaches a guard: a stand-in that records `$#` records 0.
