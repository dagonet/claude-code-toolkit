# v5.0 `cct` plugin (parts 1 + 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the toolkit repo into the Claude Code plugin `cct`. One install per machine delivers the agents, skills, report style and hooks. Projects keep only `CLAUDE.md`, the rules, `.claude/settings.json` (with the "plugin off" guard), and the native pre-push hook.

**Architecture:**
- The repo root is the plugin root, and the repo is its own marketplace (`dagonet`).
- Every hook is registered once in `hooks/hooks.json` through one wrapper, `hooks/run-hook.sh`. The wrapper:
  - classes each hook as machine-wide or project-only;
  - lets project-only hooks act only in toolkit projects (`.claude/template-manifest.json` present);
  - steps aside when the project or user settings already register the same hook script.
- A SessionStart hook writes a per-session marker. An inline PreToolUse guard in every synced project refuses every tool when the marker is missing.
- The sync stops shipping agents and hooks, apart from the pre-push set.

**Tech Stack:**
- bash hooks;
- JSON registration files;
- the Python sync server (`server/`, pytest);
- the existing test harnesses: `scripts/verify-template-consistency.sh`, `scripts/test-hooks.sh`, `scripts/test-server.sh`, `scripts/test-setup-project.sh`.

**Spec:** `docs/plans/2026-10-11-v5.0-cct-plugin-design.md`, approved in full on 2026-10-13. Read it before any task. Section numbers (§) below refer to it.

## Global Constraints

- Plugin name `cct`; marketplace name `dagonet`; install id `cct@dagonet` (§1, F7: no `claude-`/`anthropic-` prefix).
- `.claude-plugin/plugin.json` `version` == first line of `VERSION`, always (§1; F5: no bump, no update).
- The toolkit-project signal is exactly `$CLAUDE_PROJECT_DIR/.claude/template-manifest.json` exists (§3.1).
- Marker path: `${TMPDIR:-/tmp}/cct-$(id -u)/<session_id>` (§3.3). A session id is accepted only if it matches `^[A-Za-z0-9-]+$`.
- The guard message, verbatim: `BLOCKED: the cct plugin is not active in this session. Install it with /plugin marketplace add dagonet/claude-code-toolkit and /plugin install cct@dagonet, then restart the session.`
- The guard has an empty matcher. It does not honour `.claude/git-guard-off` (§3.3).
- Hook registration form: `bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.sh" <name>` (§3.5). Per-hook polarity is copied from the v4.6.1 template wrappers (table in Task 2).
- One `hooks.json` registration per hook, run in parallel. **No dispatcher** (user ruling 2026-10-12 22:17).
- Agents are named `cct:<name>`. Agent files in `agents/` carry no frontmatter `hooks:` (F4).
- Projects keep `hooks/git-pre-push.sh`, `hooks/lib/git-cmd.sh` and `hooks/lib/json.sh` (`git-cmd.sh:160` sources `json.sh`) (§3.4).
- The gate command for projects is `cct-gate` (plugin `bin/`), and the project permission is `Bash(cct-gate*)`. The toolkit repo itself keeps `bash hooks/run-gate.sh` (§3.4).
- `templates/ownership.json` `requires_skill` becomes `>=v5.0.0` (§4 step 1).
- Every file is LF. Variant-identical files: edit `templates/general/` first, then `cp` to the other five.
- Commit scripts use literal `git -C <path>` and `-F <msgfile>` (the repo's own commit gate refuses `$VAR` targets). Write multi-line logic to a script file with the Write tool, never a heredoc.
- **No task touches the live `~/.claude`, `~/.claude.json` or the installed plugins.** Installer and plugin tests use a temp `HOME`. The live rollout is Task 16, attended by the user.
- KISS: the simplest correct form. When unsure, refuse rather than model more behaviour.

## Review Focus

1. **A `session_id` with path characters** (`../x`, `a/b`, empty). The marker hook must not write outside its directory, and the guard must refuse. Pinned in Task 2 (marker) and Task 9 (guard).
2. **A plugin or checkout path containing a space** (Windows `C:/Users/First Last/...`). `run-hook.sh`, `cct-gate` and the `hooks.json` commands must quote every expansion. Pinned in Task 2 (a fixture with a space path) and Task 15 (PC smoke).
3. **A v4.x project whose settings register a hook the plugin also has.** It must run exactly once: the project copy runs and the plugin steps aside. Two `pre-commit-test` runs per commit would double a ten-minute Test. Pinned in Task 2 with the literal v4.6.1 template `settings.json` as the fixture input.
4. **A nested `claude -p` inherits the parent's session id** (spec §3.7 finding), so a child without the plugin passes the guard on the parent's marker. This is accepted as a known limit and documented in the CHANGELOG. Every test that asserts "refused without the plugin" runs with a private `TMPDIR`, so no outer marker is visible. Pinned in Task 15.
5. **A v5-synced project opened on a machine without the plugin.** Every tool is refused with the exact install message. `/plugin` slash commands still work, and after install plus restart the session works. Pinned in Task 9 (fixture) and Task 15 (smoke).

- [ ] **Step 3: Write `hooks/run-hook.sh`.**

```bash
#!/usr/bin/env bash
# cct plugin hook wrapper (v5.0 spec §3.1, §3.2, §3.5). hooks/hooks.json registers every
# toolkit hook as:  bash "${CLAUDE_PLUGIN_ROOT}/hooks/run-hook.sh" <name>
# Order: class + polarity -> toolkit-project signal (project-only hooks) -> step-aside -> exec.
# The hook is exec'd (not sourced), so its $0 and "$(dirname "$0")/lib" resolve exactly as before.
# stdin is never read here; the hook receives the payload untouched.
name="${1:-}"
here="$(cd "$(dirname "$0")" && pwd)" || exit 2
# class: machine = acts in every project (spec §3.1); project = only in a toolkit project.
# polarity on a missing script, copied from the v4.6.1 template wrappers: closed=exit 2, warn=stderr+0, open=0.
case "$name" in
  no-push-main|deny-secret-reads)                              cls=machine; pol=closed ;;
  deny-hang-shapes|model-floor|bash-output-guard|verify-hooks) cls=machine; pol=open ;;
  pre-commit-test|gate-before-merge|deny-claude-md-writes)     cls=project; pol=closed ;;
  read-size-gate|enforce-delegation|agent-budget-warn)         cls=project; pol=warn ;;
  post-edit-build|enforce-agent-contract|retro-ledger|retro-brief|now-brief) cls=project; pol=open ;;
  *) echo "HOOK BLOCKED: run-hook.sh: unknown hook name '$name' -- the plugin's hooks.json and run-hook.sh disagree" >&2; exit 2 ;;
esac
proj="${CLAUDE_PROJECT_DIR:-.}"
if [ "$cls" = project ] && [ ! -f "$proj/.claude/template-manifest.json" ]; then exit 0; fi
# step-aside (spec §3.2): the same literal substring tests as v4's user-level registrations.
s=""; [ -r "$proj/.claude/settings.json" ] && IFS= read -r -d '' s < "$proj/.claude/settings.json"
case $s in *'}/hooks/'"$name"'.sh\"'*) exit 0 ;; esac
u=""; [ -r "$HOME/.claude/settings.json" ] && IFS= read -r -d '' u < "$HOME/.claude/settings.json"
case $u in *'/hooks/'"$name"'.sh"'*) exit 0 ;; esac
f="$here/$name.sh"
if [ ! -r "$f" ]; then
  case $pol in
    closed) echo "HOOK SCRIPT MISSING: $f -- enforcement offline. Reinstall the cct plugin (/plugin install cct@dagonet)." >&2; exit 2 ;;
    warn)   echo "WARN: $f missing -- $name offline. Reinstall the cct plugin." >&2; exit 0 ;;
    *)      exit 0 ;;
  esac
fi
exec bash "$f"
```

- [ ] **Step 4: Write `hooks/cct-session.sh`.**

```bash
#!/usr/bin/env bash
# cct plugin SessionStart hook (v5.0 spec §3.3): marks this session as having the plugin loaded.
# The project's inline PreToolUse guard refuses every tool when this marker is missing.
# Runs on every source (startup, resume, clear, compact). Never blocks: always exits 0.
sid=$(cat | grep -o '"session_id" *: *"[^"]*"' | head -1 | sed 's/.*"\([^"]*\)"$/\1/')
case $sid in ''|*[!A-Za-z0-9-]*) exit 0 ;; esac
d="${TMPDIR:-/tmp}/cct-$(id -u)"
mkdir -p "$d" 2>/dev/null && chmod 700 "$d" 2>/dev/null
: > "$d/$sid" 2>/dev/null
find "$d" -type f -mtime +7 -delete 2>/dev/null
exit 0
```
