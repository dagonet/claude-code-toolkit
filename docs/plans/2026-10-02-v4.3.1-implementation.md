## Plan-level refinements of the spec (controller rulings, flagged for the user)

Each was measured on 2026-10-02 against the v4.3.0 hooks at `3a901fe` with planning probes; numbers are exit codes.

- **R-1 (G1 kill mechanism).** The spec's `taskkill //F //T //PID <winpid>` on the Test's own winpid was measured NOT to kill the tree: a cygwin `exec` breaks the Windows parent chain, and both a bash heartbeat grandchild and a native `cmd.exe` heartbeat kept writing. What worked (measured, both heartbeats stopped, 0 group members left): start the run with `set -m` (own process group, pgid = its pid), then `taskkill //F //T` on the winpid of EVERY `/proc/<pid>` whose `pgid` is that group, then `kill -KILL -- -<pgid>`. Off Git Bash: `kill -KILL -- -<pgid>`; survivors counted with `ps -A -o pgid=`.
- **R-2 (G1 scope).** The budget also wraps the Gate fallback (`bash "$RUN_GATE"`, `hooks/pre-commit-test.sh:669`). A Gate-only consumer runs its whole gate at commit time, so without this the fail-open stays open exactly where the gate is longest.
- **R-3 (G1 registrations).** There are **seven** registrations of `pre-commit-test.sh`, not eight: six `templates/*/.claude/settings.json` and the root `.claude/settings.json`. `user-level-reference/settings.json` registers no `pre-commit-test.sh` (it ships the mirror file only), and no agent frontmatter registers it either (`git grep 'pre-commit-test' -- 'templates/*/.claude/agents/*.md' 'user-level-reference/agents/*.md' '.claude/agents/*.md'` is empty). None is invented.
- **R-4 (G1 pin).** A new consistency check 64 asserts every registration carries `"timeout":` equal to the hook's own `PCT_TIMEOUT_MAX` + 60, read from the hook, with a two-sided control — so the relation cannot drift silently.
- **R-5 (G2 sites).** Wrapper words (`command`, `env A=1`, `exec`, `nohup`, `time`) already refuse (measured 2: the token walks skip non-git words); they become regression pins, not RED rows. `"git" commit` already refuses in pre-commit-test. The live misses are `git.exe`, `GIT`, `/usr/bin/git.exe`, `"git"`, `'git'` in **no-push-main** and **gate-before-merge** — first at their git-token pre-filter (`no-push-main.sh:66`, `gate-before-merge.sh:741`, which demands whitespace right after `git`), and `git.exe` everywhere. Six recognisers must agree: `is_git` in `gc_matches_subcommand`, the token test in `gc_push_args`, `gc_dash_c_list`, `gc_global_options`, and the two pre-filters. Without `gc_global_options`, `git.exe -c core.hooksPath=x commit` skips the global refusal (measured `ok`); without `gc_dash_c_list`, `git.exe -C <protected> push` is judged in the wrong repo (measured empty list). `a6_clause_class`'s first-word `git)` arm in gate-before-merge is deliberately left alone: `git.exe status` stays a "mover" there, the stricter reading.
- **R-6 (G3 mechanism — two causes, both measured).** (a) A script path is resolved against the payload cwd, not the cwd in effect where it is named: `cd sub; bash ../p.sh` → no-push-main 0. (b) Bodies are appended after the WHOLE command, so the walk judges them in whatever directory the last typed `cd` left: `bash c.sh; cd sub` → pre-commit-test 0, `bash bare.sh; cd <other repo>` → no-push-main 0, `bash m.sh; cd <other repo>` → gate-before-merge 0. Fixing (a) alone does not fix (b). The fix keeps bodies appended after the typed command (so a body's own `cd` can never move a later typed segment — measured shape `bash cdsub.sh; git commit -m x`, which refuses today and must keep refusing) and puts a **synthetic `cd <dir>`** line in front of each body, where `<dir>` is the cwd in effect at the segment that named the script; the walks already track `cd`, so the body is judged where it runs. Splicing bodies mid-command was rejected for exactly the `cdsub.sh` shape.
- **R-7 (G3 encoding).** The synthetic `cd` carries spaces as `\001` (the `gc_protect_c_paths` convention) and `gc_cd_target` decodes them. A directory containing `;`, `&`, `|`, a quote or a newline gets no synthetic `cd` (the body is appended as in v4.3.0 — no worse than today; stated as a Known limit). An unresolvable `cd` (`cd "$X"`) scans the script under every cwd seen so far, at most 8 (adds text only).
- **R-8 (S1 report location).** Pending notes are reported inside the EXISTING `once_notes_changed` INFO line. A new `verify.LINES` id would change check 58 and every count in SKILL.md step 8a/9b; one line, `; `-joined, follows the precedent of ruling R2 in `verify.py:1118-1122`.

# grandchildren running, because a cygwin exec breaks the Windows parent
# chain), then the group itself; the commit is REFUSED (exit 2). Every
# registration carries "timeout": PCT_TIMEOUT_MAX + 60 (consistency check 64),
# so this budget always fires before the harness does.
PCT_TIMEOUT_DEFAULT=540
PCT_TIMEOUT_MIN=30
PCT_TIMEOUT_MAX=3300

# pct_budget <repo> -- the budget in seconds: **Test timeout** when it is a
# whole number in PCT_TIMEOUT_MIN..PCT_TIMEOUT_MAX, else (WARN) the default.
# Unset, empty or an unfilled {{...}} placeholder is the default, silently.
# PCT_TEST_TIMEOUT_TESTONLY_S is for the fixtures only and can only SHORTEN the
# budget (1-29 s, below the configurable range): a larger value would let the
# harness kill the hook first, which is the fail-open this budget closes.
pct_budget() {
  _pb_v=$(grep -E "${GC_KEY_PRE}\*\*Test timeout\*\*:" "$1/PROJECT_CONTEXT.md" 2>/dev/null | sed -E "s/${GC_KEY_PRE}\\*\\*Test timeout\\*\\*:[[:space:]]*//;s/[[:space:]]*\$//;s/^\`//;s/\`\$//" | head -1)
  case "$_pb_v" in *\{\{*\}\}*) _pb_v="" ;; esac
  _pb_b=$PCT_TIMEOUT_DEFAULT
  if [ -n "$_pb_v" ]; then
    case "$_pb_v" in
      *[!0-9]*)
        echo "pre-commit-test: WARN **Test timeout** '$_pb_v' is not a whole number of seconds ($PCT_TIMEOUT_MIN-$PCT_TIMEOUT_MAX) -- using $PCT_TIMEOUT_DEFAULT" >&2 ;;
      *)
        if [ "${#_pb_v}" -le 5 ] && [ "$_pb_v" -ge "$PCT_TIMEOUT_MIN" ] && [ "$_pb_v" -le "$PCT_TIMEOUT_MAX" ]; then
          _pb_b=$_pb_v
        else
          echo "pre-commit-test: WARN **Test timeout** '$_pb_v' is outside $PCT_TIMEOUT_MIN-$PCT_TIMEOUT_MAX -- using $PCT_TIMEOUT_DEFAULT" >&2
        fi ;;
    esac
  fi
  case "${PCT_TEST_TIMEOUT_TESTONLY_S:-}" in
    [1-9]|1[0-9]|2[0-9]) _pb_b=$PCT_TEST_TIMEOUT_TESTONLY_S ;;
  esac
  printf '%s\n' "$_pb_b"
}

# pct_group_members <pgid> -- how many live processes are still in the group.
# Git Bash/Cygwin: /proc/<pid>/pgid (read with the builtin -- no spawn per
# process). Elsewhere: ps -A -o pgid=.
pct_group_members() {
  _pg_n=0
  if [ -r "/proc/$$/pgid" ]; then
    for _pg_d in /proc/[0-9]*; do
      _pg_g=""
      { read -r _pg_g < "$_pg_d/pgid"; } 2>/dev/null
      [ "$_pg_g" = "$1" ] && _pg_n=$((_pg_n + 1))
    done
  else
    _pg_n=$(ps -A -o pgid= 2>/dev/null | awk -v g="$1" '$1 == g { n++ } END { print n + 0 }')
  fi
  printf '%s\n' "${_pg_n:-0}"
}

# pct_kill_group <pgid> -- every member's native subtree first (Git Bash), then
# the whole group.
pct_kill_group() {
  if [ -r "/proc/$$/pgid" ]; then
    for _pk_d in /proc/[0-9]*; do
      _pk_g=""
      _pk_w=""
      { read -r _pk_g < "$_pk_d/pgid"; } 2>/dev/null
      [ "$_pk_g" = "$1" ] || continue
      { read -r _pk_w < "$_pk_d/winpid"; } 2>/dev/null
      [ -n "$_pk_w" ] && taskkill //F //T //PID "$_pk_w" >/dev/null 2>&1
    done
  fi
  kill -KILL -- "-$1" 2>/dev/null
  return 0
}

# pct_run_bounded <budget_s> <outfile> <command...> -- runs the command in a
# subshell (the containment of a consumer value's exit/exec, v2.2.5 round 5,
# lives HERE now), in its own process group, stdin from /dev/null, output to
# <outfile>. Sets PCT_RC to its exit status, or to the string "timeout" when
# the budget ran out and the group was killed; PCT_LEFT counts survivors.
# $SECONDS, not date: no spawn per tick, and a loaded machine slows the loop,
# not the clock.
pct_run_bounded() {
  _rb_budget=$1
  _rb_out=$2
  shift 2
  PCT_LEFT=0
  set -m
  ( "$@" ) > "$_rb_out" 2>&1 < /dev/null &
  _rb_pid=$!
  set +m
  # Its own process group no longer dies with this hook: if the hook itself is
  # signalled (a cancel, or a harness timeout on a registration without the
  # field), take the group down first. An uncatchable kill (SIGKILL,
  # TerminateProcess) still orphans it -- a stated Known limit.
  trap 'pct_kill_group "$_rb_pid"; exit 2' TERM INT HUP
  _rb_t0=$SECONDS
  while kill -0 "$_rb_pid" 2>/dev/null; do
    if [ $((SECONDS - _rb_t0)) -ge "$_rb_budget" ]; then
      pct_kill_group "$_rb_pid"
      wait "$_rb_pid" 2>/dev/null
      for _rb_i in 1 2 3 4 5; do
        PCT_LEFT=$(pct_group_members "$_rb_pid")
        [ "$PCT_LEFT" -eq 0 ] 2>/dev/null && break
        pct_kill_group "$_rb_pid"
        sleep 1
      done
      trap - TERM INT HUP
      PCT_RC=timeout
      return 0
    fi
    sleep 1
  done
  wait "$_rb_pid"
  PCT_RC=$?
  trap - TERM INT HUP
  return 0
}

# pct_refuse_timeout <budget> <label> -- the over-budget refusal. Never returns.
pct_refuse_timeout() {
  echo "BLOCKED: pre-commit-test: Test exceeded its $1 s budget -- commit refused. Shorten the per-commit Test (fast subset) and move the full suite to **Gate** / **Gate extra**, or raise **Test timeout** (max $PCT_TIMEOUT_MAX)." >&2
  echo "  stopped: '$2' and every process it started" >&2
  if [ "${PCT_LEFT:-0}" -gt 0 ] 2>/dev/null; then
    echo "  WARN: $PCT_LEFT process(es) of that run were still alive after the kill -- check for orphans before re-running" >&2
  fi
  echo "--- last 20 lines ---" >&2
  tail -20 "$OUT" >&2
  rm -f "$OUT"
  exit 2
}
