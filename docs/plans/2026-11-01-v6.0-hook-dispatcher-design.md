# v6.0 design: one hook dispatcher for Bash and PowerShell calls (2026-11-01)

Status: **APPROVED by the user on 2026-11-01 11:11** (dashboard #171, answer A). The answer settles the three questions in §10:
- **Q1:** Bash and PowerShell come first. Read and Edit follow only if the Bash figures meet the §6 target.
- **Q2:** the §6 target stands.
- **Q3:** the template inline guard moves to v6.1.
Direction approved by the user on 2026-10-27 06:46 ("A: one shell dispatcher per event first"); this document is the details that ruling did not cover.
Evidence: the analysis draft `2026-10-17-v6.0-mod-analysis-draft.md` §7-12 (kept outside the repo, in `~/git/.worktrees/claude-code-toolkit/`), and the measurements below. Every figure is marked **measured** or **estimate**.

## 1. Why

- Every Bash call starts 7 cct hook processes today. On the PC (Git Bash) each costs about 200 ms of CPU, even on its fast path (measured, §8 of the draft), because Git Bash process creation is slow and each hook starts about 7 programs (§10).
- **Measured on the PC (2026-10-30, `hookwall.sh`, penumbra, N=10, load green):**
  - the 7 guards started concurrently, as Claude Code runs them: median **452 ms** wall time per Bash call;
  - the same 7 run one after another, which approximates their CPU sum: **1585 ms**.
- The PC is shared by every session on it, so the CPU sum slows all of them, not only the calling session (`feedback_single_gate_stalls_machine`).
- **Goal:** much less CPU per Bash call, with wall time no worse than today. A mod (option B) stays out of scope until this has been measured.

## 2. Scope

**In v6.0:** the PreToolUse registrations that fire on a `Bash` or `PowerShell` call.

**Unchanged in v6.0:**
- **Agent:** model-floor and jev-route both return `updatedInput`, and two of those from one process would mean merging JSON.
- **The merge-tool matcher:** one guard only.
- **SessionStart, PostToolUse, SubagentStop and SessionEnd:** one hook per call, or not on the hot path.
- **`agent-budget-warn`:** it stays its own registration with no matcher (decision D3).
- **Read and Edit:** see question Q1.
- **The toolkit repo's own `.claude/settings.json`:** it registers its own copies, and the plugin steps aside for them as today.
- **No guard's decision logic changes.** Every guard still sees every Bash call; there is no substring prefilter that skips a guard.

## 3. Today (cct 5.2.1 `hooks/hooks.json`)

A Bash call collects 7 guards from 4 overlapping groups (`Bash|PowerShell`, `Read|Bash`, `Bash`, no matcher). A PowerShell call collects 4.

| Guard | Class, polarity | Bash | PowerShell |
|---|---|---|---|
| pre-commit-test (timeout 3360 s) | project, closed | yes | yes |
| no-push-main | machine, closed | yes | yes |
| gate-before-merge | project, closed | yes | yes |
| deny-secret-reads | machine, closed | yes | no |
| enforce-delegation | project, warn | yes | no |
| deny-hang-shapes | machine, open | yes | no |
| agent-budget-warn (no matcher) | project, warn | yes | yes |

**How a hook run is built today.** Each registration is its own process: `bash run-hook.sh <name>`, then `exec bash <name>.sh`.
- `run-hook.sh` decides the class (machine or project) and the polarity (what a missing script means), and steps aside when the project or the user registers its own copy.
- The guard then reads stdin with `$(cat)`, finds its lib with `$(dirname "$0")`, and parses the payload with one `node` run (`json_fields` / `json_payload`).
- A simple guard makes 6 execs (strace, Linux, §10 of the draft); pre-commit-test and enforce-delegation make 12.

## 4. Design

### D1. Registrations
- **Before:** every Bash and PowerShell guard has its own registration.
- **After:** two registrations replace them:
  - matcher `Bash`, which runs `dispatch.sh bash`;
  - matcher `PowerShell`, which runs `dispatch.sh powershell`.
  - Both use the closed preamble that the closed guards use today: if the plugin files are missing, the call is refused and the message says "restart this session".
  - Both carry `"timeout": 3360`, pre-commit-test's timeout.
- The other groups lose their Bash and PowerShell parts:
  - `Bash|PowerShell` goes away, because its three guards move into the dispatcher;
  - `Read|Bash` becomes `Read`;
  - the `Bash` group (enforce-delegation, deny-hang-shapes) goes away.
- **Result:** a Bash call starts 2 hook processes instead of 7: the dispatcher and agent-budget-warn.

### D2. The guard table and its order
- **`bash`:** no-push-main, deny-secret-reads, gate-before-merge, pre-commit-test, deny-hang-shapes, enforce-delegation.
- **`powershell`:** no-push-main, gate-before-merge, pre-commit-test.

Rule: **all closed guards first, cheapest first, with pre-commit-test last among them; then the open and warn guards.**
- A hang or crash in an open or warn guard can then never keep a closed guard from running. If a guard hangs, the timeout cancels the whole dispatcher, and Claude Code treats a cancelled hook as a non-blocking error: the call goes through.
- **Cost of this order:** a commit that a later open guard (deny-hang-shapes) refuses still runs its **Test** first. That is no regression: today all the guards run in parallel, so the Test runs then too.
- **A consistency check pins the table.** It derives the per-tool guard sets from a frozen copy of the 5.2.1 `hooks.json` (without agent-budget-warn) and asserts that the dispatcher's table names the same guards. A guard added later to one place and not the other then turns the check red.

### D3. agent-budget-warn stays a separate registration with no matcher
A matcher cannot exclude Bash, so moving this guard into the dispatchers would need one dispatcher for every tool that routes on the parsed `tool_name`. That parse is a new point of failure for every tool call. It also stays countable: today it counts every call, including calls another guard denies, and as its own registration it still does.

### D4. Running one guard
Per guard, in table order, the dispatcher:
1. **Decides class, polarity and step-aside** with the same function `run-hook.sh` uses, moved into a lib that both files source (one copy). The two settings files are read once per dispatcher run, not once per guard.
2. **Runs the guard** as `out=$( set --; . "$here/<name>.sh" </dev/null )`: one subshell fork, with no exec and no bash start.
   - `set --` clears the dispatcher's own arguments, so the guard sees no `$1`. enforce-delegation acts on `$1 = --help`, for example.
   - stdin is `/dev/null`, so a guard that still reads stdin sees an empty payload. A **closed** guard then refuses, so a missed edit there fails closed. The open and warn guards (deny-hang-shapes, enforce-delegation) exit 0 on an empty payload. For them, the replay rows in §7 catch a missed edit.
3. **Acts on the exit code:**
   - **rc 2:** stop. Exit 2. That guard's stderr has already gone to the dispatcher's stderr, and no later guard runs.
   - **Any other non-zero rc:** continue with the next guard, exactly as Claude Code treats it today: a non-blocking error, and the call proceeds. Changing that would be a separate decision for the user, not a side effect of this refactor.
   - **rc 0:** keep the guard's stdout and continue.
4. **Ends:**
   - If no guard returned 2, the dispatcher prints the stdout it kept and exits 0.
   - If two guards wrote stdout, it exits 2 ("cannot determine"), because two JSON answers cannot be concatenated.
   - **On a plain `ls` payload none of the six writes stdout.** Measured on 2026-11-01, run directly: 0 bytes from each, all rc 0. pre-commit-test's JSON records go to files under the gate directory, not to stdout. A test pins this. **Only enforce-delegation ever writes stdout:** its main-thread deny is a JSON answer with rc 0, and it is last in the `bash` table (row (s) pins that the dispatcher forwards it).
5. **Fails closed on its own errors:** an unknown table name, a missing lib or a corrupt class function exits 2. This makes the open guards fail closed when the plugin files are missing. On Bash that is already the case today, because three of its registrations use the closed preamble.

**What a guard keeps when it runs inside a subshell:**
- `exit` ends only its subshell, and the status is its verdict.
- Its `trap '[ "$?" = 127 ] && exit 2' EXIT` still fires when the subshell ends. A test row pins it.
- `set` options and variables do not leak into the next guard.
- A syntax error in a sourced guard gives rc 2, measured: `( . file )` returns 2. So a broken guard denies and stops the run, as `bash x.sh` does today.

**The dispatcher must not leak its own state into the guards.**
- Every subshell inherits the dispatcher's variables and `set` options.
- So the dispatcher's own variables carry a prefix (`cctd_`); short names like `here`, `name` or `out` would collide. It also uses no `set -e` and no `set -u`.
- A guard that expects a variable to be unset must not find a dispatcher value there.

### D5. The only edits inside the guards
The six guard scripts and `gc_read_stdin` in `hooks/lib/git-cmd.sh` get two mechanical edits. Their decision code stays as it is.
- **(a) The lib path without `dirname`.** `$(dirname "$0")` becomes a builtin path, `${BASH_SOURCE[0]%/*}`. When the path has no `/` (the guard was run as `bash x.sh` from inside `hooks/`), it falls back to `.`. Inside a sourced guard `$0` is the dispatcher; `BASH_SOURCE[0]` is the guard in both modes.
- **(b) The payload from the dispatcher, in an array.** This detail was refined by plan ruling P-1 on 2026-11-01. The guarantee is the same as the approved text; the mechanism is simpler.
  - **Where the payload is read today.** deny-secret-reads, deny-hang-shapes and enforce-delegation call `$(cat)` themselves. no-push-main and gate-before-merge do too, then pass it on with `gc_read_stdin --preparsed`. pre-commit-test reads it inside `gc_read_stdin` in `hooks/lib/git-cmd.sh`. So the edit lands in that lib function as well.
  - **The rule.** The dispatcher hands the payload over at index 1 of the indexed array `CCTD_MEMO`, the same array as the parse memo (D6). Each read site uses `${CCTD_MEMO[1]}` when the array has at least two elements, and `$(cat)` otherwise. The dispatcher `unset`s the array before filling it.
  - **Why this is enough.** Bash cannot import an array from the environment. An exported `CCTD_MEMO=x` fills index 0 only, so it can never supply a payload. No "am I sourced?" test is needed, in the guards or in a lib.
  - **The result.** An injected environment value can never replace the real payload of a guard run directly. Test rows check this from both sides, for a guard's own read and for the read in `gc_read_stdin`.
- **Run directly, every guard behaves exactly as today.** The 4231 direct-call rows in `test-hooks.sh`, the repo's own registrations and the step-aside path still run the same code.

### D6. Parse once
`json_fields` today remembers which parser works, not the parsed values.
- **The change:** the dispatcher calls `json_fields` once with the union of the fields its guards read, and `json_fields` keeps the result. A later call with the same payload text and a subset of those fields answers from that memo, with the same return code. This is one change, in `hooks/lib/json.sh` only.
- **What stays the same:** the first, real call still runs the canary and the node, python3, jq fallback. The parser matrix still means what it means today, and it runs before the release because `json.sh` changes.
- **What still starts programs:**
  - enforce-delegation keeps its own node program, because it needs node for its logic;
  - pre-commit-test keeps `git`, `sed`, `awk` and `mv`;
  - gate-before-merge keeps `git` on merge commands.

## 5. What changes in behaviour (all of it)
1. The guards run one after another, not in parallel. After a deny, the later guards do not run, and their side effects do not happen either (log lines, the Test run).
2. A deny message carries the denying guard's text, plus any warnings from guards that ran before it.
3. Every guard on Bash and PowerShell gets pre-commit-test's 3360 s timeout instead of the harness default (600 s), the closed guards included (ruling R-9). A hanging guard holds the call for up to 56 minutes, and the guards after it do not run meanwhile.
4. When the plugin files are missing, the open guards fail closed too. On Bash this is already true today, through the closed registrations.

## 6. Cost, measured and estimated
- **Process start cost (measured 2026-11-01).** The PC was at green load. The Linux figures are from load 10.7, so they are higher than idle.

  | Step | Linux, agent-host-1 | PC, Git Bash |
  |---|---|---|
  | subshell `( : )` | 0.5 ms | 8-11 ms |
  | `x=$(printf y)` | 0.5 ms | 9-14 ms |
  | `( . /dev/null )` | 0.5 ms | 8-9 ms |
  | `bash -c :` | 1.3 ms | 19-24 ms |
  | `node -e 0` | 78 ms | 44 ms (10-17) |

- **Processes per Bash call (estimate; strace measures it in the build):**

  | Guard | Execs today | After |
  |---|---|---|
  | each simple guard (no-push-main, deny-secret-reads, gate-before-merge on a non-merge call, deny-hang-shapes) | 6 (bash ×2, dirname ×2, cat, node) | 0 execs: one subshell fork plus its own `$(...)` forks |
  | pre-commit-test | 12 | about 8 (`git`, `sed`, `awk`, `mv` remain) |
  | enforce-delegation | 12 | about 9 (its own node program remains) |
  | dispatcher, once per call | none (new) | bash ×1 and one node parse |

- **PC estimate, CPU:** about 22 ms for the bash start, 44 ms for the parse, and 6 subshells at about 10 ms each, so roughly **130 ms plus the guards' own work** against 1585 ms. The guards' own work on the PC is not measured separately; the build measures it.
- **Success criterion (measured on the PC, the same `hookwall.sh` harness, penumbra, N=10, green load).** The dispatcher and agent-budget-warn start concurrently:
  - the wall time median is **at most 452 ms**;
  - the sequential sum is **at most half of 1585 ms**.

  If the build misses either, it does not ship. I report the figures instead (see Q2).

## 7. Tests
- **The existing direct rows run unchanged.** The guards still run on their own.
- **A replay through the new entry point.** Every PreToolUse row for one of the six guards is also run through `dispatch.sh bash`, and its PowerShell rows through `dispatch.sh powershell`. Each must give the same exit code and the same deny text.
- **New rows:**
  - **The payload variable is used only when sourced.** In direct mode an injected one is ignored, checked from both sides, for a guard's own read and for `gc_read_stdin`.
  - **A crash does not skip a later guard.** A guard that exits 1 still lets the next closed guard run.
  - **A syntax error denies.** A guard with a syntax error returns rc 2, so the run stops, as today.
  - **rc 2 stops the run,** and a marker shows that later guards did not run.
  - **Stdout comes out only on a final exit 0.** Two guards writing stdout give exit 2.
  - **The EXIT trap still fires** (127 becomes 2 in a subshell).
  - **A missing guard file follows its polarity.**
  - **Step-aside works per guard.** When the project registers its own copy of one guard, only that guard is skipped.
  - **Stdin is `/dev/null`.** A closed guard that still reads stdin refuses.
  - **No dispatcher arguments or variables reach a guard.** Its `$#` is 0, and no `cctd_` variable collides with it.
- **Consistency checks:**
  - the D2 table equals the frozen 5.2.1 sets;
  - `hooks.json` has no other `Bash` or `PowerShell` matchers besides the two dispatchers;
  - check 74's registration pins are updated to the new shape.
- **Before release:** the parser matrix, plus a Windows run of the replay rows by cc-toolkit-windows.

## 9. Separate item: the template's inline guard
- **What it is.** Every consumer's `.claude/settings.json` carries an inline PreToolUse command with no matcher, the "is the plugin active" check.
- **What it costs.** It runs on **every tool call** and starts `cat`, `grep`, `head`, `sed`, `id` and `uname`.
- **The easy fix, and its risk.** The fix used for `cct-session.sh` in v5.2.1 (`[[ =~ ]]`, `$UID`) is bash-only syntax. Nobody has measured yet which shell Claude Code runs hook command strings with on Linux. If it is `/bin/sh` (dash on Ubuntu), a fail-closed guard that fails to parse refuses every tool in every consumer, which is the v4.4.0 lockout again.
- **What it needs first.**
  - That shell must be measured in a temporary HOME.
  - The change reaches consumers only through `/cct:sync-template`, which you type in each consumer.
- **When.** See Q3.

## 12. Addendum (2026-11-01 20:15): fast exits, after the PC missed §6
- **What happened.** On the PC (18:51, quiet sitting), the 5.2.1 shape measured 683 ms wall and 1865 ms sum. The dispatcher measured 731 ms wall and 903 ms sum. Both targets were missed. The user chose option A at 20:03: add fast exits, then measure once more.
- **Where the time goes** (Linux strace, `ls` in penumbra, each guard against the dispatcher's prepare step alone):
  - the four simple guards add 2 forks each and no programs;
  - **pre-commit-test** adds 20 forks and starts `cat`, `awk` and `sed` (the two text rewrites in `gc_read_stdin`), then `git` and `mv` (its no-op record);
  - **enforce-delegation** adds 19 forks and starts `grep`, `head` and `cut` (the session id for the node-missing note), `node` (its whole check), then `grep` and `head` again.
- **E1. Skip the two text rewrites when they cannot change the text (`hooks/lib/git-cmd.sh`, `gc_read_stdin`).** This must be exact: `GC_CMD` stays byte-identical for every input.
  - **The join:** `cmd_join_continuations` only acts at a backslash. It runs only when `GC_CMD` contains `\`.
  - **The `-C` protection:** `gc_protect_c_paths` only acts after `-C` (case-sensitive, like its sed). It runs only when `GC_CMD` contains `-C`.
  - **The newline trap:** both run inside `$(...)`, which strips every trailing newline. When the protection is skipped, strip the trailing newlines with a builtin loop. That covers both the skipped join and the join's raw-text fallback.
  - **Who gains:** all three git guards, standalone (today's v5 registrations) and in the dispatcher. The simple guards already have their own pre-filters, so they are unchanged.
- **E2. enforce-delegation passes early on a Bash or PowerShell command that cannot be denied (`hooks/enforce-delegation.sh`).** This must be a strict superset of the node check: it only skips work that would have answered PASS.
  - **When:** only when the dispatcher's memo is present (`CCTD_MEMO[1]` set), right after `json.sh` is sourced and before `json_require_node`. It reads `tool_name` and `tool_input.command` with `json_fields`, which answers from the memo with no spawn. If `json_fields` fails, take the old path.
  - **Exit 0 when:** the tool is `Bash` or `PowerShell`, and the command contains no backslash and none of these substrings (case-sensitive, like the node regexes): `npm`, `npx`, `pytest`, `cargo`, `dotnet`, `mvn`, `gradle`, `run-gate`, `cct-gate`, `test`.
  - **Why the backslash:** node joins backslash-newline first, so `py\`+newline+`test` becomes `pytest`.
  - **Which tool names:** the superset is over the tool names the harness produces (`Bash` / `PowerShell`); a `tool_name` such as `Bash` + newline is not produced.
  - **Why `test` and no space rule:** `go test` needs `test`. The JS `\s` matches Unicode spaces that a C-locale bash pattern does not, so no whitespace is part of any pattern.
  - **What it changes:** nothing in any verdict. The node-missing note now fires on the first command that does not take the exit, not on the first command overall. The node program prints no WARN line on the Bash branch, so nothing else is lost. Standalone (Edit and Write, and v5 registrations) nothing changes.
- **Not in this round (E3).** pre-commit-test's no-op record (`git rev-parse` plus `mv`) stays. It is a deliberate diagnostic that the sync probe and earlier releases rely on. Dropping it is a separate decision for the user, and is raised only if E1 and E2 miss.

  - The "today" column runs against a 5.2.1 plugin tree, not this branch. E1 also speeds up the branch's own `run-hook.sh` path, so that column would no longer show today.
  - **The pass rule is the approved one, absolute:** wall median at most 452 ms and sum at most 792 ms. The same-sitting 5.2.1 figures are reported next to it for context only; they do not decide.
