## Items (ranked by cost saved or quality gained)

### 1. One command-shape rule causes most of all blocks

**Evidence:**
- `deny-hang-shapes` blocked 3,460 commands in 30 days: 3,037 on Linux and 423 on Windows, about 115 a day.
- On Linux, its fixed refusal texts split as follows:
  - about 2,500 were "a leading cd before several commands";
  - about 740 were "a heredoc written into a file";
  - about 250 were other shapes.
- That is more blocks than all other toolkit hooks together, and every block is one wasted model turn that re-reads the full context.
- The rule is already written in the user-level `CLAUDE.md` and in agent briefs. Agents keep producing the shape anyway, so teaching does not stick.

**Change:**
- Narrow the leading-`cd` refusal so that `cd <literal absolute path> && <commands>` passes when no git or gh command follows. Git commands keep the refusal, because the gates cannot see the effective cwd for them.
- Separately, check whether heredocs into files can be allowed when the heredoc is closed on the same command line.

**Effect:** roughly 2,000+ fewer wasted turns a month on these two machines, if most leading-`cd` blocks carry no git.
**Risk (corrected after approval, 2026-11-20):**
- The rule was added in v4.3.0 after an unattended helper hung on `cd <path>; sed …; for …`.
- Claude Code asks for permission on a compound command unless every part qualifies on its own. A `cd` outside the working directories adds its own permission rule. 2.1.325 made more compound commands ask.
- A blanket narrowing can therefore bring the hang back. It falls exactly where the blocks come from: Linux leading-`cd` blocks were 2,484 in all, 2,400 of them in subagents.
- The commands after the `cd` were mostly read-only lookups: grep 535, sed 373, wc 243, ls 177, cat 173. 241 started with git.
- The safe subset is what Claude Code documents as prompt-free: a `cd` into the session's own working directory, followed only by read-only commands. The decision went back to the user.

**Files:** `hooks/deny-hang-shapes.sh`, `scripts/test-hooks.sh`.

### 2. Claude Code 2.1.329: an erroring safety check no longer stops a Code Mode script

**Evidence:**
- Changelog 2.1.329: in Code Mode, a PreToolUse hook that errors no longer refuses the script's tool call.
- 2.1.295 and 2.1.328 add `"onFailure": "block"` for command hooks.
- None of the 20 toolkit registrations in `hooks/hooks.json` sets it.
- A deliberate refusal (exit 2) still blocks. A hook that crashes, or cannot start, now lets the call through in Code Mode.

**Change:** add `"onFailure": "block"` to every toolkit PreToolUse registration: the plugin `hooks/hooks.json`, the template `.claude/settings.json` (all six variants) and this repo's own `.claude/settings.json`. Leave out the allow-type hooks, which by design must not block on failure.
**Effect:** restores the fail-closed posture the gates were designed for.
**Risk:** a broken hook environment then blocks every call in Code Mode too, which is the existing posture outside Code Mode. Needs a parser-matrix run (hooks touched).
**Files:** `hooks/hooks.json`, `templates/*/.claude/settings.json`, `.claude/settings.json`, `user-level-reference/settings.json` (if it registers hooks).

### 3. In about 230 cases the safety checks could not run at all

**Status (v7.0.0): closed by measurement.** Both refusals stop after 2026-11-06 with none since (the check below), so there is nothing to change.

**Evidence (Linux):**
- 147 refusals read "cct plugin files are missing".
- 82 read "bash not found on PATH".
- These are the checks failing closed because their own environment was broken, not judging the command.
- A likely cause is sessions still running across a plugin update, whose plugin cache path has since been replaced.
- **Checked after approval:** counted by hour, both refusals cluster in October and early November and stop after 2026-11-06, with none since. That is after the v6.1.0 shell fix (S3) and its live update. Nothing is left to change.

**Change:** first find out when they happen, counts only by date against the plugin update dates. If they cluster after live updates, add one line to the update recipe ("restart every session right after the plugin update") and to the refusal text.
**Effect:** fewer full stops in long-running sessions.
**Risk:** none for the investigation.
**Files:** `docs/plugin-migration-windows.md`, the README update section, possibly `hooks/hooks.json` messages.

**Status (v7.0.0): shipped through the plugin split.** Nothing is removed (the user rule: low use never justifies removal). The rarely used skills and agents are optional plugins of the `dagonet` marketplace, and the core `cct` plugin keeps what every project needs.

**Evidence:**

- `challenge` had 5 starts on Linux.
- `jev` (about 90) and `sync-template` (about 70) are used.
- Every installed skill's description costs context in every session.

**Change (revised by the user, 2026-11-22):**

- First fix the counter (item 6). Then, at a later release, move rarely used parts into an **optional plugin** of the dagonet marketplace, opt-in like the six MCP server plugins. The core plugin keeps what every project needs.

**Effect:** a smaller skill list in sessions that do not opt in. Everything stays available to anyone who wants it.
**Risk:** a part someone relies on leaves the default install. The plugin split needs its own small design: which parts, the plugin name, and the migration line.
**Files:** `scripts/self-review-count.py` (now); `skills/*`, `.claude-plugin/marketplace.json`, a new `plugins/<name>/` (later).

### 6. The counter misses slash-command starts and over-counts corrections

**Evidence:**

- The correction pattern matched 10 user turns, and only 2 were corrections (20 %). The others were "no" answers to the agent's own questions.

**Change:**

**Effect:** measure 2 becomes usable, and the precision rises.
**Risk:** low; counter only, with fixtures.
**Files:** `scripts/self-review-count.py`, `scripts/fixtures/self-review/`.

- **Cheaper:** Sonnet 5.5 cache reads were cut to $0.10 per million tokens on 2026-10-07.
  - Subagent cost here is dominated by cache reads (Sonnet about 10.5 billion on Linux).

- **Default efforts differ by model:** Opus 5.5 is medium, Sonnet 5.5 high, Haiku 5.5 medium. A spawn that sets no effort therefore gets different depth per model. Worth knowing when reading Jev's effort decisions (item 8).
